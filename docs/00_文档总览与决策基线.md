## 1. 文档目的

本文件把原始 11 份方向提纲收敛为一套不相互矛盾的工程合同。V1 研发、测试和验收均以本基线为准；未来设想不得反向扩大 V1。

## 2. 权威来源与优先级

发生冲突时按以下顺序处理：

1. `docs/contracts/` 中通过 CI 校验的 OpenAPI/JSON Schema。
2. `docs/adr/` 中状态为 `Accepted` 的架构决策。
3. 本决策基线。
4. 编号文档 `01`—`12`。
5. Issue、PR 描述和临时 Prompt。

低优先级来源不能静默覆盖高优先级来源。发现冲突时，先提交文档修复，再编码。

## 3. V1 产品定义

### 3.1 目标

为企业内部数据工程团队交付一个可安装、可审计的离线批同步控制平台，完成：

`登录 → 创建项目 → 保存数据源 → 读取元数据 → 创建任务草稿 → 校验 → 发布版本 → 手动执行 → 观察日志/状态 → 验证结果 → 审计追踪`

### 3.2 目标用户

- `Admin`：系统设置、用户、项目成员、凭据策略和审计。
- `Developer`：数据源使用、任务草稿、校验与发布。
- `Operator`：执行、取消、重跑、运行监控和故障处置。
- `Viewer`：只读查看项目、任务、执行、日志和审计。

一个用户可拥有多个角色。所有权限由 API 服务端校验。

### 3.3 认证矩阵

| Reader | Writer | V1 状态 |
|---|---|---|
| MySQL 8 | MySQL 8 | 支持并测试 |
| MySQL 8 | PostgreSQL 15 | 支持并作为主验收链路 |
| PostgreSQL 15 | MySQL 8 | 支持并测试 |
| PostgreSQL 15 | PostgreSQL 15 | 支持并测试 |

“DataX 理论上支持”不等于本产品已认证。未列入矩阵的插件不得在 V1 UI 或 API 中启用。

### 3.4 支持的任务能力

- 单个 Reader、单个 Writer、单张源表、单张目标表。
- 全表读取或显式选择字段；一对一字段映射与顺序调整。
- 目标表必须预先存在；平台只做兼容性检查，不创建或修改业务表。
- 写入方式固定为 `insert-only`。
- 性能参数只开放经过边界校验的 `channel`，默认 `1`，范围 `1..16`。
- 脏数据阈值可配置绝对条数与比例；任一阈值越界即失败。
- 手动执行、取消、超时和手动重跑；重跑生成新的 Execution。

### 3.5 明确排除

V1 不支持：

- CDC、实时同步、自动增量、水位线和断点续传。
- Cron、DAG、依赖编排、补数编排和通知告警。
- 自动建表、DDL、覆盖写、upsert、truncate。
- 自由 SQL、`querySql`、`preSql`、`postSql` 和脚本转换。
- 文件、HDFS、NoSQL、云专有数据源和未认证插件。
- 插件上传、插件市场和第三方插件自动安装。
- AI 任务生成、自动诊断或自动调参。
- 多组织租户、计费、Kubernetes、多节点 HA 和异地灾备。

## 4. 技术决策摘要

| 主题 | 决策 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite + Element Plus |
| API | FastAPI 模块化单体 |
| Worker | 独立进程；唯一可启动/停止 DataX 和推进执行状态的组件 |
| 队列 | Redis；消息可重建，不是业务事实源 |
| 数据库 | PostgreSQL 15；SQLite 不属于支持路径 |
| Runtime | Alibaba DataX `datax_v202309`，JDK 8，制品/插件固定 SHA-256 |
| 部署 | Docker Compose 单节点；非 HA |
| 同步类型 | 离线批处理 |
| 密钥 | 外部主密钥 + AEAD 密文；响应、日志、预览永不返回明文 |
| 时间 | 持久化 UTC；API RFC 3339；UI 按用户时区 |
| AI | V2 能力；Provider 可插拔；未配置时完整手工功能仍可用 |

初始 Admin 不通过公开注册接口创建。全新数据库完成迁移后，由运维人员在主机上运行一次性离线 CLI，从标准输入读取临时密码；CLI 只在系统尚无用户时默认可用，成功后写入 `SYSTEM_BOOTSTRAP_ADMIN` 审计事件。后续账号全部由 Admin API 管理。

## 5. 状态与一致性语义

### 5.1 任务

- `DRAFT`：可编辑，不可执行。
- `VALID`：当前草稿通过结构、权限和兼容性校验；继续编辑会返回 `DRAFT`。
- `PUBLISHED`：生成不可变 `JobVersion`，只有版本可被执行。
- `ARCHIVED`：不再创建新执行，历史记录保留。

发布不是覆盖旧版本。每个 `JobVersion` 都有规范化配置哈希。

### 5.2 执行

`QUEUED → STARTING → RUNNING → SUCCEEDED | FAILED | TIMED_OUT | LOST`

取消路径：

`QUEUED | STARTING | RUNNING → CANCEL_REQUESTED → CANCELED`

只有 Worker 及其内置 reconciler 可写运行态和终态。API 可插入初始 `QUEUED` Execution 与取消请求，但不能直接宣告成功或失败。自动重试不进入 V1；人工重跑创建新 Execution 并关联原执行。

## 6. 术语

| 术语 | 定义 |
|---|---|
| DataX Runtime | 固定版本、只读挂载的上游 DataX 程序及认证插件集合 |
| Datasource | 连接元数据与密文凭据的项目级资源 |
| SyncJob | 可编辑任务身份，不直接执行 |
| JobVersion | 一次发布产生的不可变、可执行任务快照 |
| Execution | 对一个 JobVersion 的一次运行请求 |
| ExecutionEvent | 运行状态的追加式事件 |
| LogChunk | 带单调游标的脱敏日志块 |
| Plugin Manifest | 平台维护的插件能力、参数、敏感字段和兼容版本清单 |
| JobSpec | 与上游 DataX JSON 解耦的平台任务契约 |
| 真实 E2E | 固定 Runtime 对真实测试数据库执行并验证源/目标数据的证据 |
| 企业试点 | 可受控安装和审计，但不等同于 HA 或生产认证 |

## 7. 需求编号

- `PRD-FR-*`：功能需求。
- `PRD-BR-*`：业务规则。
- `NFR-*`：非功能要求。
- `SEC-*`：安全/隐私控制。
- `AI-*`：后续 Agent 要求。
- `ACC-*`：验收用例。

新增或删除需求时必须同步 `12_需求追踪矩阵.md`。

## 8. 文档变更控制

以下变更必须新增 ADR：

- V1 范围或认证数据源变化。
- 模块化单体/Worker/队列/事实源边界变化。
- 执行状态机、重试、幂等或版本语义变化。
- 凭据、RBAC、审计、网络或进程隔离变化。
- 新增任意 SQL、插件安装、AI 工具执行或生产自动化。

每个变更 PR 必须说明：动机、影响的需求 ID、迁移、向后兼容、安全影响、测试和回滚。

## 10. 基线完成判定

“文档齐全”要求：

- 11 份主题文档均有明确范围、异常和验收，不只是标题。
- OpenAPI 和三个 JSON Schema 可被解析和校验。
- PRD、UI、数据模型、API、测试之间有需求追踪。
- 架构、部署、安全和 Agent 边界无冲突。
- Prompt 不允许以 Mock 或静态页面冒充真实闭环。

“产品完成”则必须另行通过 `09_测试与验收标准.md`，文档完成不能替代产品验收。
