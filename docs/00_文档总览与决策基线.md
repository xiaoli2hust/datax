## 3. V1 产品定义

### 3.1 目标

为企业内部数据工程团队交付一个可安装、可审计的安全一次性离线全量复制控制平台，完成：

`登录 → 创建项目 → 管理并授权数据源 → 读取元数据 → 创建复制任务草稿 → 校验 → 发布版本 → 准备静默源表和外部独占的空目标表 → 手动执行 → 独立核验 → 审计追踪`

一次 Execution 只承诺把一张从运行前检查开始到独立 oracle 完成始终静默的源表，完整
写入一张预创建、为空且可核验的目标表。Operator/DBA 必须提交有版本、有限有效期的目标
外部独占声明，并在知悉窗口被撤回或破坏时立即报告；TargetNamespace 锁只约束平台内
并发。人工声明不是数据库强制锁或技术证明，平台无法检测全部未报告或已经回滚的外部
DML/DDL。V1 不承诺对动态变化的源表建立数据库快照，也不承诺对同一目标表进行周期性、
增量或可重复同步。

### 3.2 目标用户

- `Admin`：系统设置、用户、项目成员、端点策略、数据源、方向授权、凭据策略和审计。
- `Developer`：在获得 `SOURCE_USE` / `TARGET_USE` 授权与有效 `TransferPolicy` 后读取元数据、设计复制任务、校验与发布；不能创建或修改网络端点和数据源连接。
- `Operator`：确认源表静默与目标外部独占、在知悉独占窗口被破坏时报告、执行、取消、观察三维结果状态，以及在外部完成目标处置后发起恢复后再次执行。
- `Viewer`：只读查看项目、任务、执行、日志和审计。

一个用户可拥有多个角色。所有权限由 API 服务端校验。

| Reader | Writer | V1 状态 |
|---|---|---|
| MySQL 8 | MySQL 8 | 支持并测试 |
| MySQL 8 | PostgreSQL 15 | 支持并作为主验收链路 |

“DataX 理论上支持”不等于本产品已认证。未列入矩阵的插件不得在 V1 UI 或 API 中启用。

### 3.4 支持的任务能力

- 单个 Reader、单个 Writer、单张静默源表、单张目标表。
- 一次性读取源表全部行，可复制全部字段或显式选列；一对一字段映射与顺序调整。
- Operator 必须确认源表从运行前检查开始到独立 oracle 完成都不再发生写入；确认值和时间进入审计。
- Operator/DBA 必须提交 `target_exclusivity_confirmation`，字段固定包含
  `statement_version="1.0"`、`confirmed_at`、`valid_until` 和 `responsible_party`，
  承诺从 Worker 最后一次空表实测到 oracle 目标一致性快照读完之间无平台外 DML/DDL。
  Execution 持久化 `ACTIVE / REVOKED / EXPIRED` 状态以及撤回时的 `revoked_at/reason`；
  知悉窗口被撤回或破坏时必须调用
  `POST /executions/{execution_id}/target-exclusivity/revoke`。只有状态仍为 `ACTIVE`、
  未撤回且目标快照 `finished_at <= valid_until` 时 oracle 才可 `PASSED`。确认和实际
  快照边界进入 Execution、RuntimeSnapshot 与审计；无法保证时拒绝运行。
- 上述声明是人工前提和报告通道，不是对外部数据库写入的技术证明。平台无法检测全部
  未报告或已经回滚的外部 DML/DDL；`TargetCopyLock` 只阻止平台自身对同一
  TargetNamespace 的并发工作。
- 发布只验证目标表存在、安全画像合格且具备可核验能力，不把发布时点的空表查询保存为执行证据。目标表必须在每次运行前为空；Worker 在启动 DataX 前服务端实测并保存本次 Execution 的 `target_empty_evidence`。平台不创建、修改、清空或删除业务表。
- 写入方式固定为 `insert-only`；非空目标表、不可核验目标表以及同一 TargetNamespace
  已有 `RESERVED/ACTIVE/RECOVERY_REQUIRED` 锁时拒绝创建运行。`QUEUED` 创建事务即预留
  目标，不能排入多个同目标意图后再让后者污染恢复门禁。
- 性能参数只开放经过边界校验的 `channel`，默认 `1`，范围 `1..16`。
- 脏数据容忍固定为 `0` 条、`0%`，不提供可调入口；任何脏记录都使执行无法成为已核验成功。
- 手动执行、取消、超时和恢复后再次执行。Execution 一旦被 Worker 领取，失败、取消、超时或 `LOST` 后必须先由 Operator/DBA 在平台外完成必要处置并提交处置确认，再由独立 RecoveryProbe 持目标锁复检目标为空，之后才能创建新的 Execution；尚未领取的 `QUEUED` 取消不创建 Attempt/fence/恢复门禁，并把创建时已有的 `RESERVED` 预留转为 `RELEASED`。
- DataX 退出码 `0` 只允许进入独立核验阶段；只有 oracle 通过后，执行才可成为已核验成功。

### 3.5 明确排除

V1 不支持：

- CDC、实时同步、自动增量、水位线和断点续传。
- 非空目标追加、周期性或可重复同步，以及从运行前检查开始到独立 oracle 完成仍持续变化的动态源表。
- Cron、DAG、依赖编排、补数编排和通知告警。
- 自动建表、DDL、覆盖写、upsert、truncate。
- 自由 SQL、`querySql`、`preSql`、`postSql` 和脚本转换。
- 文件、HDFS、NoSQL、云专有数据源和未认证插件。
- 插件上传、插件市场和第三方插件自动安装。
- AI 任务生成、自动诊断或自动调参。
- 多组织租户、计费、Kubernetes、多节点 HA 和异地灾备。

### 3.6 Discovery Gate 与迁移边界

- 本文中的用户痛点和价值是待验证假设。全量实现前必须完成 8–12 名目标用户访谈、至少 20 个脱敏真实任务样本分析，以及 3 个设计伙伴合计不少于 10 个真实一次性复制任务；证据必须包含失败案例和反证。未完成时横向产品开发标记 `BLOCKED`。
- 发现工作可与有界技术 spike 并行；spike 仅用于证伪固定 Runtime、独立 oracle、目标安全预检、网络出口或 Worker 围栏等高风险假设，不计入 V1 功能完成，也不得扩展为完整管理后台或横向业务模块。
- `PRD-FR-JOB-010`（既有 DataX JSON 安全迁移）冻结为 `POST-V1`。V1 不提供导入入口；未来若立项，只能把认证白名单内的安全字段解析为新的 `DRAFT`，丢弃秘密、SQL、Transformer、自定义参数和未知插件，再重新完成授权、人工核对、校验与发布。

## 5. 状态与一致性语义

### 5.1 任务

- `DRAFT`：可编辑，不可执行。
- `VALID`：当前草稿通过结构、权限和兼容性校验；继续编辑会返回 `DRAFT`。
- `PUBLISHED`：生成不可变 `JobVersion`，只有版本可被执行。
- `ARCHIVED`：不再创建新执行，历史记录保留。

发布不是覆盖旧版本。每个 `JobVersion` 都有规范化配置哈希。

### 5.2 执行的三个独立维度

执行结果必须同时保存和展示三个维度，不能用一个“成功”徽标代替：

| 字段 | 枚举 | 含义 |
|---|---|---|
| `process_state` | `QUEUED / STARTING / RUNNING / VERIFYING / SUCCEEDED / FAILED / TIMED_OUT / CANCEL_REQUESTED / CANCELED / LOST` | 控制面、DataX 进程和核验阶段的生命周期 |
| `data_effect` | `NONE / POSSIBLE / CONFIRMED / UNKNOWN` | 目标端影响的可知程度；`CONFIRMED` 表示影响已测得（可为 0 行），不表示内容正确 |
| `verification_state` | `NOT_STARTED / VERIFYING / PASSED / FAILED / INCONCLUSIVE` | 独立 oracle 对目标结果的判断 |

主路径为：

`QUEUED → STARTING → RUNNING → VERIFYING → SUCCEEDED | FAILED`

取消路径为：

`QUEUED | STARTING | RUNNING | VERIFYING → CANCEL_REQUESTED → CANCELED`

DataX 退出码为 `0` 后只能进入 `VERIFYING`；只有独立 oracle 数据比对通过，且目标外部
独占状态仍为 `ACTIVE`、没有 `revoked_at/reason`、目标一致性快照
`finished_at <= valid_until` 时，Worker 才能写 `process_state=SUCCEEDED`、
`data_effect=CONFIRMED` 和 `verification_state=PASSED`。声明已 `REVOKED`、已
`EXPIRED` 或快照越过截止时间时不得 `PASSED`。oracle 得到 `FAILED` 或
`INCONCLUSIVE` 时 `process_state=FAILED`。DataX 失败、取消、超时或状态丢失时，
`data_effect` 必须保守记录为 `POSSIBLE` 或 `UNKNOWN`，除非有可靠证据证明为 `NONE`。

只有 Worker 及其内置 reconciler 可写运行态、核验态和终态。API 可在同一事务插入初始
`QUEUED` Execution、`TargetCopyLock=RESERVED`、初始事件/审计/幂等事实及取消请求，但
不能直接宣告复制成功或失败。自动重试不进入 V1；机器接口可
为兼容保留 `rerun` 标识，但用户动作统一称为“恢复后再次执行”，且对任何已领取执行都
必须通过处置确认、独立 RecoveryProbe 空表证据、新的源静默确认、带新
`confirmed_at/valid_until` 的目标外部独占确认和目标互斥门禁。尚未领取的 `QUEUED` 取消由 reconciler 收敛为
`CANCELED/NONE/NOT_STARTED`，释放 `RESERVED` 预留且不创建恢复门禁。

领取事务提交前失败时，事务整体回滚，Execution 仍是从未领取的 `QUEUED`，创建时已有的
目标预留仍为 `TargetCopyLock=RESERVED`，但不存在 Attempt/fence，也没有 `ACTIVE` 锁转换；
后续领取只是首次有效领取。领取事务一旦提交，任何非唯一成功
结果都不得自动回到 `QUEUED` 或复用 Attempt，必须进入恢复门禁。

## 6. 术语

| 术语 | 定义 |
|---|---|
| DataX Runtime | 固定版本、只读挂载的上游 DataX 程序及认证插件集合 |
| Datasource | 连接元数据与密文凭据的项目级资源 |
| SyncJob | 为保持机器标识兼容而保留的可编辑任务实体；面向用户统一称“复制任务”，不直接执行 |
| JobVersion | 一次发布产生的不可变、可执行任务快照 |
| Execution | 对一个 JobVersion 的一次运行请求 |
| TargetExclusivityConfirmation | `statement_version="1.0"` 的有限期人工声明；状态为 `ACTIVE / REVOKED / EXPIRED`，知悉窗口破坏时必须报告；不是外部写入未发生的技术证明 |
| TargetCopyLock | 对同一 TargetNamespace 的平台内排队、运行和恢复工作做串行化；不能阻止或证明不存在平台外 DML/DDL |
| ExecutionEvent | 运行状态的追加式事件 |
| LogChunk | 带单调游标的脱敏日志块 |
| Plugin Manifest | 平台维护的插件能力、参数、敏感字段和兼容版本清单 |
| JobSpec | 与上游 DataX JSON 解耦的平台任务契约 |
| 独立 oracle | 不复用 DataX 退出码、自报写入数或产品汇总逻辑，对静默源表与目标表执行规范化计数/摘要核验的验证器 |
| 真实 E2E | 固定 Runtime 对真实测试数据库执行一次性全量复制，并由独立 oracle 验证源/目标数据的证据 |
| 企业试点 | 可受控安装和审计，但不等同于 HA 或生产认证 |

## 8. 文档变更控制

以下变更必须新增 ADR：

- V1 范围或认证数据源变化。
- 模块化单体/Worker/队列/事实源边界变化。
- 执行三维状态、恢复后再次执行、幂等、一次性复制或版本语义变化。
- 凭据、RBAC、审计、网络或进程隔离变化。
- 新增任意 SQL、插件安装、AI 工具执行或生产自动化。

每个变更 PR 必须说明：动机、影响的需求 ID、迁移、向后兼容、安全影响、测试和回滚。
