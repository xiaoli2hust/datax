## 1. 产品决策摘要

DataX Enterprise Studio V1 是面向企业内部数据工程团队的离线批同步控制平台。它将固定版本的 Apache DataX 封装为一条可视、可控、可审计的工作链路：

`登录 → 选择项目 → 管理数据源 → 读取元数据 → 创建任务草稿 → 校验 → 发布不可变版本 → 手动执行 → 查看状态和日志 → 核对结果 → 审计追踪`

V1 不是通用 ETL、实时集成、工作流编排或 AI 平台，也不以“支持 DataX 的全部插件”为目标。V1 只承诺经过产品认证的 MySQL 8 和 PostgreSQL 15 Reader/Writer、单表离线批同步和单节点部署。

### 1.1 产品定位

- **用户价值**：让不希望直接编写和保管 DataX JSON 的团队，通过受控 UI 完成常见批同步。
- **治理价值**：把项目边界、权限、凭据、任务版本、每次执行和审计事件纳入统一事实链。
- **运维价值**：把进程状态、脱敏日志、失败原因和人工重跑集中呈现，避免依赖服务器终端。
- **安全价值**：不向浏览器、API 响应、日志或 Git 暴露明文凭据，不允许自由 SQL、脚本或自定义插件进入运行时。

### 1.2 要解决的问题

1. DataX JSON 由个人手工维护，字段、插件参数和凭据容易出错或泄露。
2. 任务缺少项目归属、版本和发布语义，无法回答“这次执行到底用了哪份配置”。
3. 执行散落在命令行和脚本中，状态、日志、取消、重跑及责任人不可统一追踪。
4. 数据源、任务和执行缺少服务端权限与审计，企业内部共享使用风险高。
5. “DataX 理论支持”常被误当成产品已验证能力，导致范围和验收失真。

## 2. 产品目标与成功定义

### 2.1 V1 目标

| 目标 ID | 目标 | 完成信号 |
|---|---|---|
| OBJ-01 | 降低认证场景的任务配置门槛 | 用户无需编辑 DataX JSON，即可完成支持矩阵内的任务发布 |
| OBJ-02 | 建立配置到执行的可追踪链路 | 每次执行都可追溯到不可变 `JobVersion`、配置哈希、Runtime 与插件版本 |
| OBJ-03 | 建立可操作的运行闭环 | 用户可手动触发、观察、取消、查看失败、人工重跑 |
| OBJ-04 | 建立最小企业治理能力 | 项目隔离、四类角色、凭据保护和关键操作审计均由服务端执行 |
| OBJ-05 | 形成可重复的真实验收 | 固定 Runtime 对真实 MySQL/PostgreSQL 测试库的 E2E 可重复执行并留存证据 |

### 2.2 产品指标

下列指标是 V1 试点和发布评价口径，不以 Mock、固定日志或静态页面计数。

| 指标 ID | 指标 | V1 目标 | 统计口径 |
|---|---|---|---|
| KPI-01 | 首个任务完成时间 | 已有可用数据源时，中位数不超过 10 分钟 | 从“新建任务”到首次发布，不含人工建目标表时间 |
| KPI-02 | 认证样例首次发布通过率 | 不低于 90% | 使用官方验收样例、未手改 JSON 的首次校验与发布 |
| KPI-03 | 执行可追溯率 | 100% | Execution 均绑定 JobVersion、配置哈希、Runtime/插件版本和触发人 |
| KPI-04 | 敏感信息泄露阻断率 | 100% | API、UI、日志、审计、测试快照和导出物的自动扫描 |
| KPI-05 | 状态一致率 | 100% | UI/API 状态与 PostgreSQL 事实记录、Worker 对账结果一致 |
| KPI-06 | 平台原因失败率 | 试点期低于 1% | 排除源/目标不可用、权限和数据约束后，由控制面或 Worker 缺陷导致的失败 |

## 3. 用户、角色与职责

V1 为**单组织、多项目**。组织不提供切换入口；项目是资源和权限边界。`Admin` 为组织级角色，其他角色按项目授予。一个用户可在不同项目拥有不同角色，权限取该项目内角色并集。

### 3.1 用户画像与 JTBD

| 角色 | 典型用户 | Job To Be Done |
|---|---|---|
| Admin | 平台管理员、安全管理员 | 当团队接入平台时，我要创建项目、账号和成员授权，确保凭据与关键操作可审计 |
| Developer | 数据工程师、任务开发者 | 当我需要同步一张表时，我要选择已授权数据源、读取元数据、完成字段映射、校验并发布版本，而不是手写 JSON |
| Operator | 数据运维、值班人员 | 当已发布任务需要运行或发生故障时，我要安全地触发、取消、查看日志并人工重跑 |
| Viewer | 项目负责人、审计或只读协作者 | 当我需要了解任务和执行情况时，我要查看配置摘要、结果、日志与审计，但不能改变系统状态 |

### 3.2 权限矩阵

所有权限必须由 API 服务端校验；隐藏菜单或按钮不能替代授权。任何角色都不能读取已保存的明文密码。

| 能力 | Admin | Developer | Operator | Viewer |
|---|:---:|:---:|:---:|:---:|
| 创建、编辑、归档项目 | ✓ | — | — | — |
| 管理用户、项目成员和角色 | ✓ | — | — | — |
| 查看被授权项目 | ✓ | ✓ | ✓ | ✓ |
| 创建、编辑、测试、归档数据源 | ✓ | ✓ | — | — |
| 查看数据源非敏感信息 | ✓ | ✓ | ✓ | ✓ |
| 创建、编辑、校验、发布、归档任务 | ✓ | ✓ | — | — |
| 查看任务和版本摘要 | ✓ | ✓ | ✓ | ✓ |
| 手动执行、取消、人工重跑 | ✓ | — | ✓ | — |
| 查看执行、指标和脱敏日志 | ✓ | ✓ | ✓ | ✓ |
| 查看本项目审计 | ✓ | ✓ | ✓ | ✓ |
| 查看跨项目审计与安全事件 | ✓ | — | — | — |

说明：

- Developer 发布后不能直接执行，避免任务开发与运行操作混同；同一用户确有需要时可同时拥有 Developer 与 Operator。
- Admin 的高权限操作也必须审计，不能绕过项目和执行状态规则。
- 用户停用后不得建立新会话；其历史发布、执行和审计记录保留原主体标识。

## 4. V1 范围

### 4.1 支持的产品能力

1. 本地账号登录、退出、修改本人密码；Admin 管理用户、项目成员和角色。
2. 项目创建、编辑、归档和项目切换；数据源、任务、版本、执行与审计均归属项目。
3. MySQL 8、PostgreSQL 15 数据源创建、编辑、连接测试和 Schema/表/字段元数据读取。
4. 单 Reader、单 Writer、单源表、单目标表的离线批任务。
5. 读取全部源字段或显式选列；一对一字段映射与顺序调整，不做表达式转换。
6. 校验目标表、目标字段、类型、长度/精度、空值约束和任务参数。
7. 草稿、校验、发布、归档；每次发布生成不可变 `JobVersion` 和配置哈希。
8. 只读、脱敏 DataX JSON 预览；用户不能直接编辑或上传 JSON。
9. 手动触发、幂等提交、排队、启动、运行、超时、取消和人工重跑。
10. 执行列表、执行详情、脱敏日志、DataX 汇总指标、失败信息和审计追踪。
11. 单节点 Docker Compose 部署；Vue 3 前端、FastAPI 模块化单体、独立 Worker、PostgreSQL、Redis 和固定 DataX Runtime。

### 4.2 Reader/Writer 认证矩阵

| Reader | Writer | V1 承诺 |
|---|---|---|
| MySQL 8 | MySQL 8 | 支持并通过真实 E2E |
| MySQL 8 | PostgreSQL 15 | 支持并作为主验收链路 |
| PostgreSQL 15 | MySQL 8 | 支持并通过真实 E2E |
| PostgreSQL 15 | PostgreSQL 15 | 支持并通过真实 E2E |

认证矩阵只表示两类数据源均可作为 Reader 或 Writer，不表示支持数据库之间的任意类型转换。平台维护单独的类型兼容矩阵；无法无损直连或安全扩宽的映射必须在发布前阻断。

### 4.3 固定技术边界

| 层 | V1 决策 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite + Element Plus |
| API | FastAPI 模块化单体；不能直接启动 DataX |
| 执行 | 独立 Worker；只有 Worker 可管理 DataX 进程树和推进运行状态 |
| 事实源 | PostgreSQL 15 |
| 队列与短期事件 | Redis；不能保存不可恢复的唯一业务状态 |
| Runtime | Alibaba DataX `datax_v202309`，JDK 8，Runtime/插件制品固定 SHA-256 |
| 部署 | 单节点 Docker Compose；明确非 HA |
| 时间 | 数据库存 UTC，API 为 RFC 3339，UI 按用户时区展示 |

## 5. V1 非目标

以下能力不进入 V1，页面、API、默认菜单和验收演示中也不能放置可误认为可用的占位入口：

- CDC、实时同步、流处理、自动增量、水位线和断点续传。
- Cron 或其他调度、DAG/工作流、依赖编排、补数编排、通知和告警。
- AI Copilot、任务生成 Agent、自动故障诊断、自动调参或模型依赖。
- 文件、HDFS、NoSQL、云专有数据源及未认证 Reader/Writer。
- 插件上传、自定义插件、插件市场或第三方插件自动安装。
- 自由 SQL、`querySql`、`preSql`、`postSql`、脚本转换和用户自定义参数片段。
- 自动建表、DDL 变更、覆盖写、`truncate`、`upsert`、`merge` 和删除目标数据。
- 多表 Join、聚合、计算字段、一对多映射、数据清洗和数据质量治理。
- 多组织租户、计费、Kubernetes、多节点 HA、自动故障转移和异地灾备。
- 生产 SSO、多环境发布流和跨项目资源共享。

## 6. 核心业务流程

### 6.1 首次接入

1. 运维人员在全新空库上运行一次性离线 `bootstrap-admin`，临时密码只从标准输入读取；非空用户库必须拒绝重复引导。
2. 初始 Admin 登录并强制修改临时密码，然后创建首个项目。
3. Admin 创建或启用用户，将 Developer、Operator、Viewer 授权到项目。
4. Admin 或 Developer 创建数据源并进行真实连接测试。
5. 平台保存连接元数据和 AEAD 密文凭据，返回内容始终脱敏。
6. 用户进入项目后只能看到该项目及其有权访问的资源。

### 6.2 任务开发与发布

1. Developer 创建 `DRAFT` 任务，选择 Reader 数据源、Schema 和源表。
2. 平台读取源字段；Developer 选择全部字段或部分字段。
3. Developer 选择 Writer 数据源、Schema 和已存在目标表。
4. 平台自动按名称推荐一对一映射；Developer 可在兼容类型内调整目标字段和顺序。
5. Developer 配置 `channel`、脏数据绝对阈值、脏数据比例阈值和执行超时。
6. 平台校验权限、数据源状态、表/字段存在性、映射完整性和类型兼容性。通过后任务进入 `VALID`。
7. Developer 查看只读脱敏 JSON 和风险摘要，确认后发布。
8. 发布生成不可变 `JobVersion`；继续编辑必须基于任务产生新草稿，不能修改历史版本。

### 6.3 手动执行与监控

1. Operator 在已发布版本上点击“运行”。
2. UI 明确提示全表、`insert-only` 和重复运行可能追加重复数据；Operator 二次确认。
3. API 进行权限和前置校验，使用幂等键创建 `Execution` 并入队。
4. Worker 从 PostgreSQL 对账并消费可重建队列，生成独立工作目录和临时运行配置，注入凭据后启动固定 Runtime。
5. 用户查看状态、耗时、记录数、字节数和脱敏日志。
6. Operator 可请求取消；Worker 负责终止完整进程树并写入最终状态。
7. 失败或超时后可人工重跑；重跑生成新的 Execution，并关联原执行，不覆盖历史。

### 6.4 异常闭环

- 连接失败：显示稳定错误码、可理解原因、下一步动作和 `request_id`，不回显密码或完整连接串。
- 元数据变化：发布前或运行前校验不通过，阻止运行并指出缺失/不兼容字段。
- Worker/主机重启：事实状态从 PostgreSQL 恢复；无法确认的在途执行进入 `LOST`，不得伪报成功。
- Redis 丢失：可从 PostgreSQL 重建待执行请求，不能丢失 Execution 事实记录。
- 目标约束失败或脏数据超阈值：执行失败，保留脱敏日志和指标；平台不自动回滚已由目标库提交的数据。

## 7. 业务规则

| 规则 ID | 规则 |
|---|---|
| PRD-BR-001 | 所有数据源、任务、版本、执行和项目级审计必须归属且只能归属一个项目。 |
| PRD-BR-002 | Admin 可跨项目；其他角色只能访问明确授权项目。资源不存在与无权限的响应不得泄露跨项目资源信息。 |
| PRD-BR-003 | 数据源仅允许 MySQL 8 或 PostgreSQL 15。密码创建时必填；编辑时不提交 `password` 字段表示不变，`null` 或空字符串无效；任何读取接口不返回原值。 |
| PRD-BR-004 | 单任务只能选择一个 Reader、一个 Writer、一个源表和一个目标表；源与目标不能是同一数据源的同一表。 |
| PRD-BR-005 | 目标表必须预先存在。平台不得创建、修改、清空或删除业务表。 |
| PRD-BR-006 | 写入固定为 `insert-only`。每次运行读取当前源表的全部行；重复运行可能产生重复数据或唯一键冲突，平台不提供去重承诺。 |
| PRD-BR-007 | 字段必须一对一映射；映射数为 1..2048；目标字段不能被重复映射；不允许常量、表达式、脚本或 SQL。 |
| PRD-BR-008 | 目标类型必须在认证兼容矩阵内，并满足长度、精度、标度和空值约束；不安全的隐式缩窄必须阻断。 |
| PRD-BR-009 | 性能只开放 `channel`，默认 `1`，范围 `1..16`。其他 DataX 参数由平台固定，不接受用户 JSON 片段。 |
| PRD-BR-010 | 脏数据条数范围为 0..1,000,000，比例范围为 0..1；执行超时为 60..604,800 秒，默认 3600 秒。任一脏数据阈值越界即判定执行失败。 |
| PRD-BR-011 | 任务状态为 `DRAFT → VALID → PUBLISHED → ARCHIVED`。编辑已校验草稿会回到 `DRAFT`；历史 JobVersion 永不可变。 |
| PRD-BR-012 | 只有 `PUBLISHED` 版本可执行；任务归档后不得创建新执行，历史版本、执行和审计继续可读。 |
| PRD-BR-013 | 执行状态为 `QUEUED → STARTING → RUNNING → SUCCEEDED / FAILED / TIMED_OUT / LOST`；取消路径为 `QUEUED / STARTING / RUNNING → CANCEL_REQUESTED → CANCELED`。 |
| PRD-BR-014 | 只有 Worker 可写运行态和最终态。API 只能创建执行、记录取消请求，不能直接宣告执行成功。 |
| PRD-BR-015 | V1 无自动重试。人工重跑必须绑定原 JobVersion、创建新 Execution，并记录 `rerun_of_execution_id`。 |
| PRD-BR-016 | 同一运行请求的幂等键在 24 小时有效期内重复提交只能创建一个 Execution；用户明确再次运行必须使用新幂等键。 |
| PRD-BR-017 | 每次 Execution 固化 JobVersion、规范化配置哈希、Runtime 版本、插件版本、触发人和触发时间。 |
| PRD-BR-018 | DataX JSON 预览只读且脱敏。实际凭据仅在 Worker 运行时按需解密，临时文件最小权限并在结束后清理。 |
| PRD-BR-019 | 发布、数据源变更/测试、授权、执行、取消、重跑和归档必须产生不可变审计事件。 |
| PRD-BR-020 | 项目、数据源和任务优先软删除/归档；存在引用或历史执行时禁止物理删除。 |
| PRD-BR-021 | 所有列表稳定排序并分页；所有写操作使用幂等控制或乐观锁，版本冲突不能静默覆盖。 |
| PRD-BR-022 | 日志、表名、字段名和数据库错误均视为不可信输入；展示时转义，日志需脱敏并限制单次读取大小。 |

## 8. 功能需求与用户故事

### 8.1 认证、项目与权限

| 需求 ID | 用户故事 | 验收摘要 |
|---|---|---|
| PRD-FR-AUTH-001 | 作为用户，我要使用本地账号登录和退出，以访问被授权项目。 | 正确凭据建立会话；错误凭据返回统一错误；停用用户不能登录；退出后令牌失效。 |
| PRD-FR-AUTH-002 | 作为用户，我要修改本人密码，以控制账号安全。 | 校验旧密码和密码策略；成功后撤销其他会话；全程不记录明文。 |
| PRD-FR-AUTH-003 | 作为运维人员，我要在全新部署上安全创建唯一的初始 Admin，以便系统在没有公开注册入口的情况下完成首次接入。 | 仅空用户库允许一次性离线引导；临时密码从标准输入读取且不进入参数、环境、日志或审计；成功后首次登录强制改密，重复引导被拒绝。 |
| PRD-FR-PRJ-001 | 作为 Admin，我要创建、编辑和归档项目，以隔离资源与权限。 | 项目标识（slug）唯一且创建后不可变；归档前检查运行中执行；归档后禁止新增和执行。 |
| PRD-FR-PRJ-002 | 作为 Admin，我要管理用户、项目成员与四类角色。 | 授权即时生效；越权 API 返回 403；每次变更写审计。 |
| PRD-FR-PRJ-003 | 作为多项目用户，我要切换当前项目。 | 切换后列表、统计和可操作项全部按项目刷新；URL 深链仍做服务端授权。 |

### 8.2 数据源

| 需求 ID | 用户故事 | 验收摘要 |
|---|---|---|
| PRD-FR-DS-001 | 作为 Developer，我要创建和编辑 MySQL/PostgreSQL 数据源。 | 字段校验完整；密码密文保存；名称在项目内唯一；类型创建后不可变。 |

## 9. 非功能需求

| 需求 ID | 类别 | 要求 |
|---|---|---|
| NFR-PERF-001 | 控制面性能 | 在验收数据量和 20 个并发 UI 会话下，非外部依赖的读 API P95 ≤ 800 ms、写 API P95 ≤ 1.5 s。 |
| NFR-PERF-002 | 运行反馈 | 手动运行提交后 2 秒内返回 Execution；Worker 产生新状态或日志后，正常网络下 UI P95 在 3 秒内可见。 |
| NFR-SCALE-001 | 单节点容量 | V1 单 Worker 默认最大并行 Execution 为 `1`；超过上限的执行必须保持 `QUEUED`，不能超配启动。部署可调高，但调高后必须重新完成资源与稳定性验收。 |
| NFR-REL-001 | 事实一致性 | PostgreSQL 是唯一业务事实源；Redis 清空后可重建待处理执行，不得丢失 Execution 或产生伪成功。 |
| NFR-REL-002 | 故障恢复 | API、Worker 或主机重启后必须对账在途执行；无法确认的状态进入 `LOST`。V1 不承诺不停机或自动故障转移。 |
| NFR-SEC-001 | 凭据安全 | 凭据使用外部主密钥和 AEAD 加密；响应、日志、审计、预览、导出、异常和测试快照不得包含明文。 |
| NFR-SEC-002 | 进程安全 | Worker 使用参数数组启动固定 Runtime，禁止 `shell=True`、命令字符串拼接和用户可控可执行路径；每次运行使用隔离工作目录。 |
| NFR-SEC-003 | 访问控制 | 所有资源读写均校验组织、项目、角色和资源状态；越权、横向访问及对象枚举测试必须通过。 |
| NFR-AUD-001 | 审计 | 凭据、授权、发布、执行、取消、重跑和归档操作 100% 产生含主体、对象、结果、时间和 request_id 的审计事件。 |
| NFR-OBS-001 | 可观测性 | API、Worker 和 Execution 使用可关联 ID；健康检查区分 API、PostgreSQL、Redis、Worker 和 Runtime 可用性。 |
| NFR-COMP-001 | 兼容性 | 仅认证 MySQL 8、PostgreSQL 15、DataX `datax_v202309`、JDK 8 和固定插件摘要；版本漂移必须阻断启动或明确标记不受支持。 |
| NFR-DATA-001 | 保留与清理 | Execution/ExecutionEvent 默认保留 365 天，脱敏运行日志 30 天，审计 730 天，幂等记录 24 小时；可延长，缩短须经 Admin 与合规负责人批准。清理不得破坏引用；运行临时凭据和工作目录在结束后及时清理。 |
| NFR-UX-001 | 可访问性 | 核心流程满足键盘可达、可见焦点、表单标签、非颜色单一编码和 WCAG 2.1 AA 对比度要求。 |
| NFR-DEP-001 | 部署边界 | V1 仅单节点 Docker Compose，维护、重启和主机故障会造成服务中断；UI 与文档不得暗示 HA。 |

外部数据库速度、网络带宽和源/目标锁竞争不属于控制面响应 SLA；数据吞吐只在固定验收数据集和环境中记录，不泛化为生产承诺。

## 10. 数据与指标口径

### 10.1 首页指标

| 指标 | 定义 |
|---|---|
| 已发布任务 | 当前项目中至少有一个可执行 JobVersion 且未归档的任务数 |
| 24 小时执行数 | 触发时间位于最近 24 小时的全部 Execution |
| 成功率 | `SUCCEEDED / (SUCCEEDED + FAILED + TIMED_OUT + LOST)`；排队、运行、取消不进入分母 |
| 运行中 | 当前状态为 `STARTING` 或 `RUNNING` 的执行数 |
| 排队中 | 当前状态为 `QUEUED` 的执行数 |
| 失败待处理 | 最近 24 小时内 `FAILED / TIMED_OUT / LOST` 且尚无成功人工重跑的执行数 |
| 同步记录数 | 时间范围内 `SUCCEEDED` 执行由 DataX 汇总报告的写入记录数之和 |

所有卡片和图表必须显示时间范围与项目范围；点击后带相同筛选条件下钻，避免首页与列表口径不一致。

### 10.2 运行结果口径

- `SUCCEEDED` 表示 DataX 进程退出码为 0，且 Worker 已完成进程终结与状态落库，不等于业务层自动对账完成。日志汇总解析使用独立状态；解析失败不得反向把已确认的执行结果改成成功或失败。
- 平台展示 DataX 报告的读取/写入记录数、字节数、速率、脏记录数和耗时；缺失指标显示“未采集”，不能显示 `0` 冒充。
- V1 不承诺目标端事务性全量回滚。失败执行可能已经写入部分数据，错误页和重跑确认必须提醒用户先核对目标表。

## 11. 风险与缓解

| 风险 ID | 风险 | 影响 | V1 缓解 |
|---|---|---|---|
| RSK-01 | `insert-only` 全表重复运行导致重复行或唯一键冲突 | 数据正确性 | 运行和重跑前强提示；保留版本/执行证据；不宣称幂等数据写入 |
| RSK-02 | 源/目标 Schema 在发布后漂移 | 执行失败或类型错误 | 运行前轻量校验；不兼容时阻断并要求创建新版本 |
| RSK-03 | DataX/JDK/插件版本漂移 | 结果不可重复 | 固定 Runtime 与插件 SHA-256；启动和执行记录版本摘要 |
| RSK-04 | 日志、异常或临时 JSON 泄露凭据 | 安全事件 | AEAD、运行时注入、脱敏管线、隔离工作目录、结束清理与泄露扫描 |
| RSK-05 | Worker 或主机中断造成运行态不确定 | 错误状态或孤儿进程 | 进程树管理、Worker 心跳、启动对账和 `LOST` 终态 |
| RSK-06 | Redis 故障或数据丢失 | 排队停滞 | PostgreSQL 保存请求事实；队列可重建；Redis 不保存唯一状态 |
| RSK-07 | 单节点资源竞争 | 控制面变慢、执行失败 | Worker 并发上限、容器资源限制、队列背压和容量测试 |
| RSK-08 | 类型兼容矩阵覆盖不足 | 发布后失败或数据截断 | 只允许认证类型映射；缩窄阻断；真实双向 E2E 覆盖 |
| RSK-09 | 取消无法撤销已提交的目标数据 | 部分写入 | 文案明确“停止进程不等于回滚”；保留指标与处置建议 |
| RSK-10 | “企业级”被误解为 HA/生产认证 | 采购和运维预期错误 | README、部署页和验收报告持续标注单节点、非 HA、未生产批准 |

## 12. 发布验收

### 12.1 验收前置条件

- 使用固定摘要的 DataX `datax_v202309`、JDK 8、MySQL 8 和 PostgreSQL 15。
- 使用真实容器/进程、真实数据库和固定可复现数据集；Mock 只能用于单元测试。
- 保存 Runtime/插件摘要、环境配置摘要、测试时间、用例结果和脱敏日志。
- 缺少真实 Runtime 或数据库时标记 `BLOCKED`，不得以静态日志或假状态替代。

### 12.2 产品验收用例

| 验收 ID | Given / When / Then | 通过条件 |
|---|---|---|
| ACC-PRD-001 | Given Admin 创建两个项目并分别授权用户；When 用户访问本项目和另一项目资源；Then 仅本项目可见。 | 菜单、列表、详情和 API 均无横向越权；拒绝请求带稳定错误码和审计。 |
| ACC-PRD-002 | Given MySQL 8 与 PostgreSQL 15 的有效和无效凭据；When 创建并测试数据源；Then 有效连接可读取元数据，无效连接给出可操作错误。 | 密码不出现在响应、日志、审计、预览或测试产物；服务重启后仍可使用密文凭据测试。 |
| ACC-PRD-003 | Given 四种 Reader/Writer 组合和预建目标表；When 分别创建全字段与选列任务并发布；Then 平台生成可执行 JobVersion。 | 四种组合均通过真实校验；映射、版本号、配置哈希、Runtime/插件版本完整保存。 |
| ACC-PRD-004 | Given 不兼容类型、缺失目标字段、目标非空无默认字段或同表自同步；When 校验任务；Then 发布被阻断。 | 错误定位到具体步骤和字段；修正后可重新校验；无自由 SQL 或 JSON 绕过入口。 |
| ACC-PRD-005 | Given 源表含固定行数和可核对内容；When Operator 确认风险并执行已发布版本；Then 状态按合法路径推进并完成写入。 | 目标记录数和验收校验和符合预期；Execution 绑定完整快照；UI 未提前显示成功。 |
| ACC-PRD-006 | Given 用户双击运行或网络重试相同请求；When 相同幂等键到达 API；Then 只创建一个执行。 | PostgreSQL 仅一条 Execution；审计能解释重复请求；新一次显式运行可创建新 Execution。 |
| ACC-PRD-007 | Given 一个长时间运行任务；When Operator 请求取消；Then 状态进入 `CANCEL_REQUESTED`，由 Worker 终止进程树并对账。 | 最终为 `CANCELED` 或有明确失败状态；不存在孤儿 DataX 进程；页面提示目标端可能已有部分写入。 |
| ACC-PRD-008 | Given 一个失败、超时或丢失执行；When Operator 人工重跑；Then 创建关联原执行的新 Execution。 | 原记录不可变；新执行沿用原 JobVersion；历史、日志和审计均可分别查看。 |
| ACC-PRD-009 | Given Worker 运行中被强制终止且 Redis 被清空；When 服务恢复并对账；Then PostgreSQL 事实记录保持完整。 | 待执行请求可重建；不确定在途执行进入 `LOST`；没有伪造 `SUCCEEDED`。 |
| ACC-PRD-010 | Given 日志中注入密码样例、ANSI 控制符、HTML 和超长行；When 查看、搜索、下载日志；Then 内容安全呈现。 | 明文凭据不可检出；脚本不执行；分页/游标稳定；超限有明确截断说明。 |
| ACC-PRD-011 | Given 超过脏数据绝对或比例阈值；When DataX 结束；Then 执行判定失败。 | 阈值、实际脏数据数和失败原因可见；不把进程退出或部分写入误报为成功。 |
| ACC-PRD-012 | Given 单节点服务停止；When 用户访问或执行任务；Then 产品明确不可用而非宣称自动切换。 | 恢复后完成状态对账；文档、系统信息页和验收报告均明确“单节点、非 HA”。 |
| ACC-PRD-013 | Given 已完成迁移的全新空用户库；When 运维人员通过标准输入运行一次性 `bootstrap-admin`，随后尝试再次运行；Then 首次创建唯一 Admin，重复引导被拒绝。 | 临时密码不出现在进程参数、环境、日志、审计或 Git；写入 `SYSTEM_BOOTSTRAP_ADMIN` 审计；首次登录强制改密。 |

### 12.3 V1 完成门禁

只有同时满足以下条件，才可声明“V1 功能完成”：

1. 本文所有 P0 功能需求、业务规则和非功能要求都有实现、自动测试及可追踪证据。
2. 四种 Reader/Writer 组合的真实 E2E 全部通过，主链路包含 MySQL 8 → PostgreSQL 15 和 PostgreSQL 15 → MySQL 8。
3. 权限、凭据、命令/路径安全、取消、崩溃对账、Redis 重建和日志脱敏测试通过。
4. `02_产品信息架构与UI设计.md` 的关键流程、失败态、权限态、危险操作和可访问性验收通过。
5. 安装、备份恢复、升级回滚和已知限制有真实验证记录。
6. 未验证项被明确列为 `BLOCKED` 或后续项；不得用页面可点击、容器构建或 Mock 结果替代。

## 13. 后续版本方向

V2/V3 可评估调度、DAG、告警、更多认证插件、插件市场、AI 辅助、CDC 和 HA，但每项都必须先完成独立 PRD、威胁模型、ADR、契约、数据迁移和真实验收设计。后续能力不能成为 V1 启动或手工流程的依赖。
