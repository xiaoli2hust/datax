## 1. 设计目标与边界

V1 UI 服务于一条明确的安全一次性离线全量复制闭环：

`登录 → 进入项目 → 使用已授权数据源 → 创建复制任务草稿 → 字段映射 → 校验 → 发布版本 → 准备静默源表与空目标表 → 手动运行 → 独立核验 → 必要时恢复 → 查看审计`

### 1.1 设计原则

1. **事实优先**：界面只展示后端已确认的事实。提交执行后显示“已提交/排队中”；DataX 退出 `0` 后显示“核验中”，只有独立 oracle `PASSED` 才显示“复制已核验成功”。
2. **项目先行**：除组织级系统管理外，页面始终处于明确项目上下文；项目切换后数据、权限和统计一起切换。
3. **高信息密度但可扫描**：列表支持筛选、稳定排序、分页和列管理；详情用摘要、时间线和页签分层。
4. **强反馈**：长操作有阶段、耗时、取消或重试入口；错误包含原因、下一步动作、稳定错误码和 `request_id`。
5. **风险可见**：`insert-only`、一次性全表读取、源表静默、目标表为空、取消不等于回滚和恢复门禁等风险必须出现在动作发生前。
6. **安全默认**：密码、完整连接串、运行时 JSON 和敏感日志不进入浏览器；服务端授权是最终边界。
7. **不伪装能力**：V1 不出现 AI、调度、DAG、告警、插件市场、CDC 或自定义 SQL 的可用入口和假结果。
8. **一次性复制语义**：日志增量刷新可称为“运行日志更新”，不能称为“实时数据同步”；非空目标追加、动态源表和周期性运行不得出现可用入口。
9. **本机边界可见**：界面明确显示“Windows 本地工作站、非 HA”；不出现外部服务器、
   局域网共享或后台跨关机运行的暗示。产品 URL 固定为 `http://127.0.0.1:17860`。

### 1.2 Windows 安装、Launcher 与浏览器边界

V1 的“桌面产品”指 Windows 安装与启动体验，不是把业务系统改写为纯原生单进程
`.exe`。用户路径如下：

`运行 Setup.exe → 检查 Windows 11 x64 / WSL2 / Docker Desktop → 安装 Launcher 与桌面快捷方式 → 双击快捷方式 → 启动并检查本机容器 → 默认浏览器打开 127.0.0.1:17860`

- `Setup.exe` 和 Launcher 不安装 Docker Desktop、不点击或代替用户接受许可，也不使用
  伪装环境规避许可。缺失 WSL2/Docker Desktop 时停止并链接官方指引；完成前置安装后由
  用户主动重试。
- Launcher 显示 `未启动 / 启动中 / 可用 / 降级 / 停止中 / 已停止 / 启动失败`，提供
  “启动并打开”“打开控制台”“停止服务”“复制诊断信息”四类本机动作。重复启动复用
  现有 Compose，不创建第二套数据或端口。
- 健康检查通过后才打开系统默认浏览器的 `http://127.0.0.1:17860`。浏览器关闭不停止
  服务；停止必须由用户在 Launcher 中明确执行，若存在运行中/核验中 Execution 则给出
  强风险提示，但停止动作不能伪装成业务取消或数据回滚。
- 仅 Web 反向代理映射宿主 `127.0.0.1:17860`；API 通过同源路径访问，API、Worker、
  PostgreSQL 不映射宿主端口。界面不提供“允许局域网访问”“绑定所有网卡”或公网发布入口。
- Windows 睡眠、关机、重启、Docker Desktop 停止或升级期间产品不可用；重新启动后先
  展示“正在恢复并对账”，在 reconciler 完成前禁用新运行。
- 卸载默认保留本机数据库、密钥和证据目录；用户选择一并删除时必须二次确认，并明确
  “历史记录与密文将不可恢复”。浏览器页面不得自行删除宿主数据目录。

### 1.3 Discovery Gate 对 UI 交付的约束

企业试点或公开发布前必须完成 Discovery Gate：8–12 名目标用户访谈、至少 20 个脱敏
真实任务样本分析，以及 3 个设计伙伴合计不少于 10 个真实一次性复制任务。按 ADR-0007，
所有者可授权风险自担的 UI 工程候选；候选页面和内部验证不产生 Discovery 证据，也不能
让 UI 试点、发布或完成门禁转为 PASS。

### 1.4 视觉方向

- Windows 桌面尺寸浏览器优先的企业控制台，浅色主题为 V1 默认；“桌面优先”不表示
  页面运行在原生 WebView 或全部能力位于一个 `.exe`。
- 信息色用于普通提示，成功/警告/危险色只表达状态，不承担唯一识别作用。
- 页面标题、项目、资源名称和当前状态形成稳定的视觉层级。
- 表格默认紧凑密度；表单使用舒适密度；高风险确认采用独立对话框。
- Logo 与品牌色在品牌验收前使用中性标识，不复制第三方商标。

## 2. 全局信息架构

### 2.1 应用框架

| 区域 | 内容 | 规则 |
|---|---|---|
| 顶栏左侧 | 产品标识、当前项目选择器 | 项目内页面始终显示当前项目；切换前处理未保存内容 |
| 顶栏右侧 | “本机工作站”标识、API/Worker 健康状态入口、帮助、用户菜单 | 持续标明仅本机可用、非 HA；不提供 V1 无告警能力的“通知中心” |
| 左侧主导航 | 首页、数据源、复制任务、运行中心、审计日志 | 根据项目权限展示；隐藏入口不替代服务端鉴权 |
| 左侧管理导航 | 项目管理、用户与授权 | 仅 Admin 显示 |
| 内容区 | 面包屑、页面标题、说明、主操作、页面主体 | 主操作每页最多一个高强调按钮 |
| 全局反馈层 | Toast、消息条、确认框、错误抽屉 | Toast 不承载必须保留的错误详情 |

## 3. 权限在界面中的表现

| 操作 | Admin | Developer | Operator | Viewer |
|---|:---:|:---:|:---:|:---:|
| 项目/用户管理入口 | 显示 | 隐藏 | 隐藏 | 隐藏 |
| EndpointPolicy、数据源新建/编辑/测试/归档 | 显示 | 隐藏 | 隐藏 | 隐藏 |
| 方向授权与 TransferPolicy 审批 | 显示 | 隐藏 | 隐藏 | 隐藏 |
| 数据源完整 `host / port / database / username` 与 host 筛选 | 显示 | 隐藏 | 隐藏 | 隐藏 |
| 复制任务新建、编辑、校验、发布、归档 | 显示 | 显示 | 隐藏 | 隐藏 |
| 运行、取消、处置确认、恢复后再次执行 | 显示 | 隐藏 | 显示 | 隐藏 |
| 数据源别名/引擎/用途状态/脱敏摘要，以及任务/版本/执行/日志查看 | 显示 | 显示 | 显示 | 显示 |
| 项目审计查看 | 显示 | 显示 | 显示 | 显示 |
| 全组织审计查看 | 显示 | 隐藏 | 隐藏 | 隐藏 |

交互规则：

- 用户没有某动作权限时，默认隐藏动作；若为了理解流程而保留，则禁用并说明“需要 Operator 角色”，不得只显示无解释的灰色按钮。
- 通过 URL 直接访问无权页面时进入 403；资源标识不属于当前项目时不能泄露其名称、存在性或属性。
- 角色在用户停留页面期间被撤销时，下一次请求返回 403，界面清除敏感缓存并提示刷新权限。
- 多角色按当前项目取并集，但不能绕过 Admin 管理的 EndpointPolicy、`SOURCE_USE` / `TARGET_USE` 和 TransferPolicy。例如同时拥有 Developer 与 Operator 的用户可设计、发布并运行，但不能自行注册目标端点。

## 4. 全局交互与页面状态

### 4.1 标准页面结构

每个列表页按以下顺序组织：

1. 面包屑、页面标题和一句范围说明。
2. 右上角主操作。
3. 筛选条：关键词、状态、类型、时间范围和“重置”。
4. 结果摘要：当前项目、筛选条件、总数和最后刷新时间。
5. 表格：稳定默认排序、分页、列设置和行操作。
6. 空态、错误态或内容。

每个详情页按以下顺序组织：

1. 返回入口、资源名称、状态徽标和主动作。
2. 关键摘要：项目、版本、负责人、时间、关联资源。
3. 风险或异常消息条。
4. 页签内容。
5. 审计和关联对象深链。

### 4.2 通用状态规范

| 状态 | UI 行为 | 禁止行为 |
|---|---|---|
| 首次加载 | 使用与最终布局一致的 Skeleton；危险动作禁用 | 用全屏转圈遮住全局导航；展示旧项目数据 |
| 后台刷新 | 保留现有内容，显示“更新中”和最后更新时间 | 清空列表造成跳动 |
| 无数据 | 说明当前范围并给有权限用户一个下一步动作 | 用演示数据填充 |
| 筛选无结果 | 显示当前筛选摘要和“清除筛选” | 当成系统无数据 |
| 可恢复错误 | 保留安全的旧内容，显示原因、重试和 request_id | 吞错后显示成功 |
| 首屏失败 | 展示错误页、重试、帮助信息和 request_id | 永久 Loading |
| 无权限 | 403 页面或局部权限态，给返回入口 | 暴露资源名称、密钥或跨项目信息 |
| 会话过期 | 保存非敏感本地草稿提示，跳转登录；登录后回原路由 | 静默丢失输入 |
| 网络断开 | 顶部持续消息条“连接已中断”；读内容标记可能过期 | 把未确认写操作显示为成功 |
| 乐观锁冲突 | 409 冲突页展示“重新加载”和安全的只读差异摘要 | 静默覆盖他人修改 |
| 服务降级 | 分别标识 API、数据库、Worker、Runtime、独立 oracle 状态 | 只显示笼统“系统异常” |
| 本机恢复对账 | 持续显示“Windows/Docker 恢复后正在对账”，历史只读可用，新运行禁用 | 在 reconciler 完成前接受新运行或显示“一切正常” |

### 4.3 表格与筛选

- 列表必须服务端分页，默认每页 20 条，可选 20/50/100。
- 默认排序必须稳定；同一时间戳使用不可变 ID 作为次级排序键。
- URL 保存筛选、页码和排序，刷新与返回后可恢复。
- 关键词搜索明确搜索字段，不提供未定义的“全局万能搜索”。
- 批量高风险操作不进入 V1；用户逐项确认，降低跨项目误操作。
- 空值显示“—”，未采集指标显示“未采集”，不得把缺失值显示为 `0`。

## 5. 页面详细设计

### 5.0 Windows 安装、启动与首次引导

**安装器**

- 发布安装包必须先通过签名和发布哈希校验；无效、缺失或不匹配时阻断安装并显示可核对的
  发布信息，不提供“忽略并继续”。
- 首屏写明“仅支持 Windows 11 x64；需要 WSL2 与 Docker Desktop；核心服务运行在
  Linux 容器中；不需要外部 Linux 服务器；本产品不是纯原生单进程 `.exe`”。
- 前置检查分别显示 Windows 版本/架构、硬件虚拟化、WSL2、Docker Desktop 安装状态和
  Docker Engine 可用性。每项只显示必要的非敏感摘要。
- 缺失项使用“查看官方安装说明”和“重新检查”，不提供静默安装/自动同意；Docker 许可
  文案要求用户或其组织自行评估，产品不作许可适用性结论。
- 安装位置与本机数据/密钥目录分开展示。升级沿用数据目录；卸载默认保留数据，选择删除
  时另起危险确认，不得用默认勾选诱导删除。
- 成功页提供“创建桌面快捷方式”（默认选中）、“立即启动”和明确入口
  `http://127.0.0.1:17860`，但浏览器必须等健康检查成功后再打开。

**Launcher**

| 状态 | 主文案 | 主动作 |
|---|---|---|
| `PREREQUISITE_BLOCKED` | 缺少或无法使用 WSL2/Docker Desktop | 查看官方指引、重新检查 |
| `STOPPED` | 本机服务未启动 | 启动并打开 |
| `STARTING` | 正在启动本机容器并检查服务 | 查看进度；禁止重复启动 |
| `RECONCILING` | 服务已恢复，正在对账在途执行 | 打开只读控制台；新运行暂不可用 |
| `READY` | 本机服务可用 | 打开控制台、停止服务 |
| `DEGRADED` | 部分组件不可用 | 查看组件状态、复制诊断信息、重试 |
| `STOPPING` | 正在停止本机服务 | 等待；禁止再次停止 |
| `FAILED` | 启动失败 | 展示安全错误摘要、复制诊断信息、重试 |

- Launcher 启停命令必须使用参数数组；诊断信息不包含密码、连接串、主密钥、完整 Runtime
  JSON 或未脱敏日志。
- 用户关闭 Launcher 窗口时不能把“关闭窗口”伪装成“停止服务”。若设计为后台驻留，必须
  有可发现的托盘入口；若不驻留，桌面快捷方式再次打开时从真实 Compose 状态恢复显示。
- 停止前若存在 `STARTING / RUNNING / VERIFYING / CANCEL_REQUESTED` Execution，显示
  “停止本机服务不等于取消或回滚，恢复后该执行可能进入 LOST/恢复门禁”，要求再次确认。
- 启动/停止失败必须保留真实状态；不得仅用定时器切换成成功。默认浏览器打不开时，保留
  可复制的 `http://127.0.0.1:17860`，不改用局域网 IP。

**初始 Admin**

- 仅在空用户库显示 Launcher 的本机首次引导对话框；输入登录邮箱、显示名、临时密码和
  确认密码。
- Launcher 通过受控子进程的标准输入调用容器内 `bootstrap-admin`；密码不能进入命令
  参数、环境、URL、浏览器、剪贴板默认内容、日志或 Launcher 持久化。

  显示安全错误而不暴露现有账号。

### 5.4 用户与授权（Admin）

**列表字段**

登录邮箱、显示名、状态、项目数、角色摘要、上次登录时间、创建时间、操作。

**编辑字段**

| 字段 | 校验 |
|---|---|
| 登录邮箱 | 必填；合法邮箱；最长 254 字符；创建后不可修改 |
| 显示名 | 必填；1–128 字符 |
| 初始密码/新密码 | 至少 12 字符并满足服务端密码策略；不回显 |
| 状态 | `ACTIVE`、`LOCKED`、`DISABLED`；`LOCKED` 由安全策略产生，不作为普通手工选择 |
| 项目与角色 | 每个项目可多选 Developer/Operator/Viewer；Admin 为组织级授权 |

**交互**

- 停用用户前显示其运行中执行；停用账号不自动取消已在 Worker 中运行的进程。
- 重置密码后只显示一次临时凭据或安全重置结果；页面刷新后不可再次读取。
- 角色变更对话框按项目分组，保存前展示新增和移除差异。
- 用户不能停用自己的最后一个 Admin 账号；服务端和 UI 双重阻断。

### 5.5 端点策略（Admin）

端点策略是组织级网络白名单，不是数据源表单里的普通提示。列表显示名称、数据库引擎、精确 FQDN/IP、允许 CIDR、端口、TLS 要求、DNS TTL 上限、状态、更新人与更新时间。

- 只允许 `EXACT_FQDN` 或 `EXACT_IP`，不提供通配域名、URL、路径或自由连接串。
- 保存前展示 DNS 解析和 CIDR/出口预检结果；预检通过不替代 Worker 运行时重解析与真实出口强制。
- 停用前列出受影响数据源、TransferPolicy 和已发布任务；停用后阻断新测试、发布与执行，不改变历史证据。
- 创建、修改、启停都使用乐观锁并产生审计；非 Admin 深链访问返回 403。

### 5.6 数据源列表

**列表字段**

- Admin：名称、引擎、完整 `host / port / database / username`、用途授权、状态、最近连接测试、引用任务数、更新人、更新时间和操作。
- Developer/Operator/Viewer：仅显示别名、引擎、获准用途、状态和不可逆脱敏摘要；不返回或渲染完整 `host / port / database / username`，也不通过 Tooltip、复制、导出、错误文案或前端缓存携带隐藏原值。

**筛选**

- Admin：关键词（名称/主机）以及引擎、状态、最近测试结果；只有 Admin 可按完整 host 筛选。
- Developer/Operator/Viewer：仅可按别名、引擎、获准用途和状态筛选。服务端不能用隐藏 host/database/username 参与其关键词搜索，也不能通过匹配数量、排序差异或“有结果/无结果”反推出内部主机。

**动作**

- Admin：新建、编辑、测试连接、停用、归档，配置方向授权与 TransferPolicy。
- Developer：查看获准使用的数据源别名、引擎、用途/状态和脱敏摘要，并读取对应方向的元数据；详情响应不包含完整端点字段。
- Operator/Viewer：仅查看别名、引擎、用途/状态和脱敏摘要。
- 行内测试为异步动作，显示“测试中…”；用户离开页面后结果仍以服务端记录为准。
- 通用数据源页打开元数据抽屉时不自动假定 `SOURCE_USE`；Developer 或 Admin 必须先明确选择“作为复制源”或“作为复制目标”，请求再分别携带 `SOURCE_USE` 或 `TARGET_USE`。切换用途必须清空已有结果和分页游标；未获对应用途授权时展示服务端 403，不得自动回退到另一用途。

数据源详情沿用同一字段级权限：只有 Admin 可查看完整 `host / port / database / username`。其他角色即使直接访问详情深链、修改查询参数或调用列表/详情/搜索接口，也只能得到上述非敏感字段；脱敏摘要必须不可逆且不能保留足以枚举内网主机的前后缀。

**空态**

- Admin：“当前项目还没有数据源。请先配置 EndpointPolicy，再创建第一个 MySQL 或 PostgreSQL 数据源。”
- 其他角色：“当前项目还没有获准使用的数据源，请联系 Admin 配置方向授权。”

### 5.7 新建/编辑数据源

本页面仅 Admin 可访问。Developer 不显示数据源端点表单，也不能通过深链提交。

**字段**

| 字段 | 控件与校验 |
|---|---|
| 名称 | 必填；2–128 字符；项目内唯一 |
| 类型 | MySQL 8 / PostgreSQL 15；修改时必须选择引擎匹配的 ACTIVE EndpointPolicy，并在服务端真实探针通过后创建新 DatasourceRevision |
| 主机 | 必填；仅主机名或 IP，不含协议、路径和 JDBC 参数 |
| 端口 | 必填；1–65535；MySQL 默认 3306，PostgreSQL 默认 5432 |
| 数据库 | 必填；1–128 字符；不接受 SQL 或连接串 |
| 默认 Schema | PostgreSQL 必填，默认 `public`；MySQL 隐藏该项 |
| 用户名 | 必填；1–128 字符 |
| 密码 | 新建必填；编辑显示“已保存”，用户未输入新值时前端不提交该字段；`null` 或空字符串不能发送为新密码 |
| SSL 模式 | `DISABLE`、`REQUIRE`、`VERIFY_CA`、`VERIFY_FULL`；默认及允许值由部署安全策略约束 |
| 描述 | 0–1000 字符 |

平台从受控字段生成 JDBC URL，并要求主机、DNS 解析与真实出口均命中 Admin 预置的 EndpointPolicy。`VERIFY_CA/VERIFY_FULL` 使用部署方预置的信任库；V1 不上传证书文件。仅可呈现插件 Manifest 白名单内的非敏感枚举项，不提供自由连接串、任意 JDBC 参数、SQL 初始化脚本、证书路径或插件选择输入框。

**交互顺序**

1. 用户填写字段。
2. 点击“测试连接”；界面显示阶段、耗时和可取消的 UI 等待状态，但不声称已取消后端测试。
3. 成功时显示数据库类型/版本摘要和测试时间；失败时显示安全错误摘要、建议动作、错误码和 request_id。
4. 允许保存未测试草稿，但该数据源标记“未验证”，不能用于任务发布。
5. 编辑连接字段后，先前测试结果标记“已过期”，必须重新测试。

编辑保存不是原地覆盖：任一 `endpoint_policy_id / engine / host / port / database_name /
default_schema / username / ssl_mode` 变化时，API 必须先用待采用配置和当前凭据完成
EndpointPolicy、DNS、精确出口、TLS/认证与物理实例身份探针；全部通过后才新增不可变
`DatasourceRevision` 并切换 current pointer。探针失败时页面保留原配置并展示稳定错误，
不得保存“待验证修订”。仅名称/说明变化不创建连接修订。

**危险状态**

- 停用：确认后阻止新发布和新执行；历史可见。
- 凭据轮换：要求输入新密码并重新测试；永不显示旧密码。
- 凭据轮换只有在新密码真实探针通过后才新增并切换 secret；失败时继续使用原 secret，
  不得先退役旧版本或显示轮换成功。
- 紧急撤销：当前仅有 Admin API，尚无已实现的页面按钮；任何页面不得把“轮换”伪装成
  `REVOKED/COMPROMISED`。未来 UI 只能向 Admin 提供带原因码、二次确认和影响摘要的入口，
  明确说明它会禁用 current 数据源、对已绑定或尚未领取且将绑定该 secret 的工作建立安全终止
  事实；Execution 会进入失败/恢复门禁，RecoveryProbe 会使 Gate=`REJECTED`，不能显示为
  “已安全回滚”或“即时停止”。
- 归档：有已发布任务引用时阻断并列出任务链接；无引用时二次确认。

**方向授权与 TransferPolicy**

- Admin 可按成员分别授予 `SOURCE_USE`、`TARGET_USE`；授权差异在保存前明确展示。
- 项目“复制方向策略”页按源/目标 DatasourceRevision、物理端点、表、分类和状态筛选；
  新建策略必须选择精确修订，不能只绑定可变 Datasource ID。
- 表单必须继续选择源/目标 catalog/database、schema、表及显式允许列。选择“全部列”时
  服务端先解析为当前显式列清单再申请审批，不能保存动态通配符。
- 提交审批前展示规范化 scope JSON、源列→目标列集合和完整 `scope_hash`；审批页显示同一
  hash。任何表/列/scope 修改都创建新 DRAFT/hash 并使旧审批失效。
- TransferPolicy 使用 `DRAFT → PENDING_APPROVAL → ACTIVE / REJECTED / REVOKED` 的契约状态；状态不是 `ACTIVE` 时，任务发布与执行均阻断。
- `SENSITIVE` 策略显示“双人批准”状态，创建者不能完成第二次批准；未由两个不同 Admin 批准时保持 `BLOCKED`。
- 任务向导只显示 mapping 完全属于当前 ACTIVE `scope_hash` 的表列；发布与运行都由
  服务端重新验证 JobSpec mapping 是该 scope 的子集。
- UI 只表达审批与策略事实，真实 DNS 和网络出口仍由服务端/运行环境强制执行。

### 5.8 复制任务列表

**列表字段**

任务名称、状态、最新发布版本、Reader → Writer、源表 → 目标表、最近执行状态、最近执行时间、更新人、更新时间、操作。

**筛选**

关键词（任务名/表名）、任务状态、Reader 类型、Writer 类型、最近执行状态。

**状态动作**

- `DRAFT`：Admin/Developer 可继续编辑、校验；若已有历史发布版本，Admin/Operator 仍可显式运行该不可变版本。
- `VALID`：Admin/Developer 可发布；任意配置编辑后回到 `DRAFT`；若已有历史发布版本仍可显式运行。
- `PUBLISHED`：Admin/Operator 可运行最新发布版本；Admin/Developer 可“基于当前版本编辑”。
- `ARCHIVED`：只读，不显示运行按钮。

列表中的运行按钮只在任务未归档、至少存在一个已发布版本、用户具备 Admin 或 Operator 任一权限且 Worker 可用时显示。任务处于 `DRAFT/VALID` 且已有旧版本时，按钮文案为“运行已发布的 vN”，避免误以为运行当前草稿。

### 5.9 新建/编辑任务向导

向导共五步，不包含调度、DAG、告警、AI、SQL 或插件选择。

#### 步骤 1：基本信息

| 字段 | 校验 |
|---|---|
| 任务名称 | 必填；2–128 字符；项目内唯一 |
| 描述 | 0–1000 字符 |

- 创建即生成 `DRAFT`。
- 编辑已发布任务时，界面明确“正在创建新草稿，历史版本不会改变”。

#### 步骤 2：Reader 与源字段

| 字段 | 规则 |
|---|---|
| Reader 数据源 | 仅当前项目、已启用、测试有效且当前 Developer 具有 `SOURCE_USE` 的 MySQL/PostgreSQL |
| Schema | PostgreSQL 必选；MySQL 使用数据库范围 |
| 源表 | 单选；支持服务端搜索和分页 |
| 字段模式 | “全部字段”或“选择字段” |
| 源字段 | 至少 1 个、最多 2048 个；选列模式显式勾选；显示名称、类型、长度/精度、可空、主键 |

- 表和字段来自真实元数据接口，不允许自由输入表名、SQL 或通配符。
- 源表必须从运行前检查开始到独立 oracle 完成始终停止写入；向导只说明该责任，不用复选框假装已经形成快照。
- 更换数据源或源表会清空下游映射；确认框列出将丢失的步骤数据。
- 元数据加载失败保留已保存标识，但禁止继续校验并提供重试。

#### 步骤 3：Writer 与字段映射

| 字段 | 规则 |
|---|---|
| Writer 数据源 | 仅当前项目、已启用、测试有效、当前 Developer 具有 `TARGET_USE`，且与 Reader 修订之间存在 `ACTIVE` TransferPolicy 的 MySQL/PostgreSQL |
| Schema | PostgreSQL 必选；MySQL 使用数据库范围 |
| 目标表 | 必须从真实元数据中选择、可由服务端只读核验，不能创建新表 |
| 字段映射 | 每个源字段恰好映射一个不重复目标字段 |

映射表显示：

- 顺序；
- 源字段名、源类型、可空；
- 目标字段选择、目标类型、可空/默认值；
- 兼容结果：兼容、警告、阻断；
- 具体原因和修复建议。

交互规则：

- 首次加载按同名且兼容推荐，推荐不等于自动通过。
- 支持上移/下移按钮和键盘操作，不以拖拽作为唯一排序方式。
- 同一目标字段被重复选择时立即阻断。
- 目标必填字段未映射且无默认值时阻断。
- 源与目标解析为同一物理数据库实例中的同一规范化表身份时阻断；不同 Datasource、revision、hostname 或 IP 别名不能绕过。
- 发布校验只判定目标表存在、安全画像合格且具备可核验能力；不查询或冻结发布时点的空表事实。“为空”由 Worker 在每次启动 DataX 前重新实测，不能由设计阶段或客户端声明替代。
- 不支持的类型、缩窄、长度/精度不足或时区语义不明时阻断；不做隐式截断或猜测。

#### 步骤 4：运行参数

| 字段 | 默认值 | 校验 |
|---|---:|---|
| Channel | 1 | 整数，1–16 |
| 脏数据策略 | 0 条 / 0% | V1 只读固定值；不提供编辑，任一脏记录即失败 |
| 执行超时 | 60 分钟 | 整数，1–10,080 分钟（60–604,800 秒） |

- 前端生成 JobSpec 时始终提交 `record_count=0`、`percentage=0`；服务端拒绝被篡改的
  非零值。非零容忍不以隐藏开关进入 V1。
- 写入模式固定显示为只读 `insert-only`。
- 读取范围固定显示为“一次执行读取静默源表全部行”；V1 无 where 条件、水位线、动态源表或周期同步。
- 不显示 batchSize、速度字节阈值、错误重试、自定义 JSON 等未开放参数。

#### 步骤 5：校验、预览与发布

页面从上到下展示：

1. 配置摘要：Reader/Writer、表、字段数、`channel`、阈值、超时。
2. 固定策略摘要：`OPERATOR_QUIESCED / EMPTY_AND_VERIFIABLE / INSERT_ONLY_ONCE / REJECT_NONEMPTY_TARGET / MANUAL_REMEDIATE`。
3. 风险消息：“这是一次性全量复制。源表必须从运行前检查开始到独立 oracle 完成始终保持静默；目标表必须预创建、为空且可核验。平台不会创建、清空或修改业务表。”
4. 校验清单：方向授权、TransferPolicy、数据源修订、表/字段存在性、类型兼容、目标安全画像、目标可核验能力和参数；发布校验不以目标当时为空作为通过条件。
5. 问题列表：错误、警告、所属步骤、字段和“前往修复”。
6. 脱敏 DataX JSON：只读、格式化、可复制脱敏内容；禁止编辑或下载含密钥版本。
7. “发布版本”主按钮：仅校验通过且无配置变化时启用。

发布确认文案必须包含新版本号、配置哈希短码、Reader/Writer 摘要和“发布后版本不可修改”。发布成功后进入任务详情，而不是自动运行。

#### 向导通用行为

- 每一步可“保存草稿并退出”；自动保存只能保存已通过本地校验的非敏感表单值。
- 页签、刷新和返回前提示未保存更改；不得把密码、完整连接串或完整运行 JSON 存入浏览器持久存储。
- 后退保留已保存数据；更改上游选择时明确清理受影响的下游数据。
- 保存发生 409 时显示当前版本与服务器版本摘要，用户选择重新加载或复制自己输入，不能静默合并。
- 校验期间按钮显示进度并防重复；超时后允许重试，不生成“通过”状态。

#### 既有 DataX JSON 安全迁移（`POST-V1`）

`PRD-FR-JOB-010` 已冻结为 `POST-V1`。V1 任务列表、向导、路由和 API 帮助均不显示“从 DataX JSON 解析草稿”入口，也不把内部解析 spike 计为 UI 能力。未来单独立项时必须满足：

- 上传内容只在受控解析器中处理，不能直接执行、预览为可执行配置或写入运行目录；
- 只提取认证 Reader/Writer、单表和一对一字段映射到新的 `DRAFT`；
- 密码、Token、连接串、自由 SQL、Transformer、自定义参数、未知插件和未知字段全部丢弃并逐项报告；
- 用户必须重新选择已授权的 DatasourceRevision 和 TransferPolicy，人工核对、校验并发布；
- 解析结果不能显示“迁移成功”，只显示“已生成待核对草稿”。

该能力不属于 V1 完成门禁；即使未来已完成内部 spike，未通过单独的安全与真实样本验收前仍不得显示入口。

**页头**

任务名称、状态、Reader → Writer、最新发布版本、更新人/时间，以及按权限显示的编辑、发布、运行、归档动作。

**页签**

| 页签 | 内容 |
|---|---|
| 概览 | 数据源、表、字段数、参数、最新执行、风险摘要 |
| 当前草稿 | 草稿状态、上次校验、问题数；仅 Admin/Developer 可编辑 |
| 已发布版本 | 版本号、哈希、发布人、发布时间、Runtime/插件版本 |
| 执行历史 | 该任务的执行列表与状态 |
| 审计 | 该任务相关审计事件 |

**版本对比**

- 对比基本信息、Reader/Writer、表、字段增删/映射、参数和配置哈希。
- 敏感字段统一显示 `••••••`；相同密文变化也只显示“凭据引用已变更”。
- 历史版本完全只读；不提供直接修改或覆盖入口。

### 5.11 运行前确认

运行由 Admin 或 Operator 发起。对话框展示：

- 任务名和 JobVersion；
- 源表、目标表和字段数；
- 固定一次性策略与 `insert-only` 写入方式；
- 源表必须从运行前检查开始到独立 oracle 完成始终保持静默；
- 目标表必须预创建、为空且可核验；空表由 Worker 服务端实测，不是用户豁免；
- Operator/DBA 必须保证从 Worker 最后一次空表实测到 oracle 目标一致性快照读完没有
  平台外 DML/DDL；平台 TargetNamespace 锁只约束平台内执行；
- 该保证是有截止时间和报告义务的人工声明，不是技术证明；平台无法检测全部未报告或
  已经回滚的外部 DML/DDL；
- 同一 TargetNamespace 已有 `RESERVED/ACTIVE/RECOVERY_REQUIRED` 锁时阻断；
- DataX 退出 `0` 后仍需独立核验；
- 执行超时；

Operator 必须分别勾选：

1. “我已确认源表停止写入，并会从运行前检查开始保持静默到独立 oracle 完成”；
2. “我已与目标表所有者确认：从 Worker 最后一次空表实测到 oracle 目标一致性快照读完，
   不会发生平台外 DML/DDL；我理解平台锁不能阻止外部系统写入。”

前端提交 `source_quiescence_confirmation` 和 `target_exclusivity_confirmation`，服务端记录
确认人、时间与声明版本；不得提供“忽略非空目标/外部写入风险继续”。目标声明区域必须
展示并提交：

- 只读声明版本 `statement_version="1.0"`；
- 责任主体 `responsible_party=OPERATOR | DBA`；
- 确认时间 `confirmed_at`；
- 明确的截止时间 `valid_until`，并提示必须覆盖预计执行和目标 oracle 快照读完时间；
- 可选非敏感备注。

`valid_until <= confirmed_at` 时禁用提交。界面不得把较长有效期表述为更强的技术保障，也
不得声称系统会自动发现所有外部写入。

主按钮文案为“确认并提交执行”，不能使用“开始复制成功”。提交后：

- 服务端返回 Execution ID，跳转执行详情；
- 相同幂等请求只显示同一执行；不同幂等键提交同一 TargetNamespace 时，第二个请求显示
  “目标已被排队或执行占用”及已有 Execution 的安全引用；
- 未收到明确响应时显示“提交结果待确认”，通过幂等查询确认，不能让用户盲目重复创建。
- Worker 完成服务端空表复检前显示“检查目标表”；非空、不可核验、授权过期或目标被占用时持久显示阻断原因与 request_id。

### 5.12 运行中心

**列表字段**

执行编号、任务、版本、进程状态、数据影响、核验状态、目标外部独占状态、触发人、排队
时间、开始时间、结束时间、耗时、已核验记录数、操作。

**筛选**

关键词（执行编号/任务名）、`process_state`、`data_effect`、`verification_state`、
`target_exclusivity_status`、任务、版本、触发人、时间范围、是否为恢复后再次执行。

**自动刷新**

- V1 单 Worker 默认同时运行 1 个 Execution；超出部署并发上限的执行保持“排队中”。
  无论全局并发如何配置，同一 TargetNamespace 只允许一个未释放的排队预留、活动或恢复锁。
- 默认每 5 秒增量刷新活动执行；用户可暂停。
- 页面不可见时降低刷新频率，恢复可见时立即对账。
- 新状态未确认前保留旧状态和“更新中”标识，不猜测终态。
- 断线时显示持续消息条；恢复后从服务端重新获取事实状态。

### 5.13 执行详情与日志

**页头与摘要**

- 执行编号、状态徽标、任务、JobVersion、触发人、触发时间。
- 配置哈希、Runtime 版本、插件版本。
- 源/目标 DatasourceRevision、方向授权/TransferPolicy 版本、源静默确认和服务端 `target_empty_evidence`。
- 目标外部独占声明的版本、责任主体、确认/截止时间、`ACTIVE / REVOKED / EXPIRED`
  状态，以及存在时的 `revoked_at/reason`；同时标注“人工声明，不是技术锁”。
- 排队、启动、运行、结束时间和耗时。
- 恢复来源、RecoveryGate 或后继执行链接。
- Admin/Operator 按状态看到“取消”“撤回/报告独占窗口破坏”或“开始恢复”；未通过恢复
  门禁不显示“恢复后再次执行”按钮。

**目标外部独占声明**

- 非终态且状态为 `ACTIVE` 时，Operator/Admin 始终可点击“撤回/报告独占窗口破坏”。
  对话框要求选择
  `OPERATOR_REVOKED / DBA_REVOKED / EXTERNAL_DML_DDL_REPORTED / CHANGE_FREEZE_BROKEN`，
  展示 `reported_at` 并允许填写非敏感备注；确认后调用
  `POST /executions/{execution_id}/target-exclusivity/revoke`。
- 服务端接受后显示 `REVOKED`、`revoked_at` 与原因。未领取执行随后取消并释放
  `RESERVED`；已领取执行请求终止并进入恢复门禁；已在 `VERIFYING` 时显示
  `INCONCLUSIVE / TARGET_EXCLUSIVITY_BROKEN`，均不得显示成功。
- Worker/reconciler 评估当前时间超过 `valid_until` 时显示 `EXPIRED` 和
  `VALIDITY_WINDOW_EXPIRED`。已经结束的 Execution 保留当时结论，不因页面当前时间自动
  改写历史。
- 页面持续提示：Operator/DBA 知悉窗口被撤回、冻结失效或发生平台外 DML/DDL 时必须立即
  报告；平台无法检测全部未报告或已经回滚的外部 DML/DDL。

**状态时间线**

逐项展示 `process_state`、目标独占确认/撤回/过期事件、时间、来源
（API/Worker/oracle/对账）和安全摘要；在摘要区始终并列展示 `data_effect`、
`verification_state` 与 `target_exclusivity_status`。`LOST` 必须解释为“平台无法确认
DataX 最终结果，目标可能已写入；必须完成必要外部处置（无需清理时如实记录理由）并通过
恢复门禁”，不能归入普通失败。

**指标**

独立 oracle 的源/目标行数、规范化摘要、规则版本和证据时间作为“核验指标”；读取记录数、DataX 自报写入记录数、字节数、平均速率、脏数据条数/比例和退出码作为“进程诊断指标”。两组必须分区，诊断指标不能显示为已核验记录数。没有采集到的值显示“未采集”。

**错误区**

稳定错误码、人类可读摘要、可能原因、建议动作、request_id、脱敏技术详情。`data_effect=POSSIBLE/UNKNOWN` 或核验未通过时显示持久警告，并引导进入恢复流程，不提供绕过门禁的“恢复后再次执行”。

**日志查看器**

- 默认只显示脱敏文本；HTML 以文本转义，ANSI 控制字符不执行。
- 使用单调游标增量读取，显示“已连接/重连中/已暂停/已结束”。
- 支持自动滚动开关、暂停、继续、关键词搜索、复制选中内容和下载脱敏日志。
- 大日志使用虚拟列表或分块加载，不能一次把全量日志放入 DOM。
- 日志被保留策略清理时显示“日志已按保留策略清理”，执行元数据仍可查看。
- 默认保留口径为：脱敏运行日志 30 天，Execution/ExecutionEvent 365 天；页面显示按服务端返回计算的实际到期时间。
- 日志流断开不改变执行状态；重连从最后确认游标继续。

**取消确认**

文案：

> 取消会请求 Worker 停止 DataX 进程，但不能撤销已提交到目标库的数据。是否继续？

确认后按钮进入“取消请求已提交”，直到 Worker 写入 `CANCELED` 或其他终态。不得在 API 接受请求时直接显示“已取消”。

**故障恢复与恢复后再次执行**

仅对已领取且目标锁为 `RECOVERY_REQUIRED` 的 `FAILED / TIMED_OUT / CANCELED / LOST` 显示“开始恢复”，不显示可绕过门禁的“恢复后再次执行”；未领取取消不显示恢复入口：

1. 持久显示原 Execution 的 `data_effect`、核验结果和“平台不会清理业务表”。
2. Operator/DBA 在平台外完成必要处置；若确认无需清理，必须如实记录理由。
3. Operator 提交 `remediation_confirmation`：处置方式、是否清理及理由、确认时间和非敏感备注；页面不能接收 SQL、密码或数据库转储。
4. 独立 RecoveryProbe 持有目标互斥权只读复检目标为空。复检通过显示
   `RecoveryGate=VERIFIED` 及证据时间；仅提交确认、目标非空或无法核验时保持
   `BLOCKED`。
5. “恢复后再次执行”对话框引用 `recovery_gate_id`，要求新的
   `source_quiescence_confirmation`，以及 `statement_version="1.0"`、新
   `confirmed_at/valid_until`、`responsible_party` 完整的
   `target_exclusivity_confirmation`。提交后创建新 Execution、关联原执行并跳转；原记录
   与证据不改变。

机器 API 可为兼容保留 `/rerun` 和 `rerun_of_execution_id`，但用户文案不得暗示重复执行本身是安全的。

### 5.14 审计日志

**项目审计字段**

时间、操作者、角色、动作、对象类型、对象名称/ID、结果、来源 IP 摘要、request_id。

**筛选**

时间范围、操作者、动作、对象类型、结果。Admin 可在组织级页面增加项目筛选。

**详情**

- 展示脱敏前后差异、错误码和关联资源链接。
- 密码、Token、完整连接串、Runtime JSON 和日志敏感片段不得展示。
- 审计为只读，不提供编辑或删除入口。
- 审计默认保留 730 天；若部署策略依法延长，以服务端返回的保留信息为准。
- 非 Admin 只能查看当前授权项目；跨项目对象以安全方式拒绝。

### 5.15 个人资料

- 显示登录邮箱（不可改）、显示名、项目与角色摘要。
- 默认使用浏览器时区。用户可为当前设备选择展示时区，该非敏感偏好仅保存在本地且 V1 不跨设备同步；所有服务端时间仍为 UTC/RFC 3339。
- 修改密码要求旧密码、新密码和确认密码；成功后提示其他会话已失效。
- 退出登录需清除浏览器中的会话和非必要项目缓存。

### 5.16 403、404 与服务异常

- 403：“你没有访问此页面的权限。”提供返回当前项目首页，不展示目标资源名称。
- 404：“页面不存在或已被移除。”无权限资源也可按安全策略返回 404。
- 401：跳转登录，并保留安全的回跳路径。
- 500/503：展示安全摘要、错误码、request_id、发生时间、重试和复制诊断信息。
- Worker/Runtime 不可用属于局部服务异常：只禁用新运行，任务查看和历史记录仍可用。
- Windows/Docker 恢复后尚未完成对账时属于受控恢复态：历史只读可用，新运行入口持续
  禁用并显示 Launcher 状态，不得让用户通过刷新页面绕过。

## 6. 状态、徽标与术语

### 6.1 任务状态

| 后端值 | 中文标签 | 颜色/图标语义 | 可用动作 |
|---|---|---|---|
| `DRAFT` | 草稿 | 中性 + 编辑图标 | 编辑、校验；若有历史发布版本，可按权限运行该版本 |
| `VALID` | 已校验 | 信息色 + 对勾轮廓 | 发布、继续编辑；若有历史发布版本，可按权限运行该版本 |
| `PUBLISHED` | 已发布 | 成功色 + 版本图标 | 运行（Admin/Operator）、基于版本编辑、归档 |
| `ARCHIVED` | 已归档 | 中性 + 归档图标 | 只读查看 |

### 6.2 执行三维状态

`process_state`：

| 后端值 | 中文标签 | UI 说明 |
|---|---|---|
| `QUEUED` | 排队中 | 已创建执行，等待 Worker 资源 |
| `STARTING` | 启动中 | Worker 正在准备工作目录和启动 Runtime |
| `RUNNING` | 运行中 | DataX 进程运行，日志持续更新 |
| `VERIFYING` | 核验中 | DataX 已退出，独立 oracle 正在核验；不能显示复制成功 |
| `CANCEL_REQUESTED` | 取消中 | 已接受请求，等待 Worker 终止并对账 |
| `SUCCEEDED` | 复制已核验成功 | 仅允许与 `data_effect=CONFIRMED`、`verification_state=PASSED` 同时出现 |
| `FAILED` | 失败 | 已确认失败；显示错误码和处置建议 |
| `TIMED_OUT` | 已超时 | 超过配置时间并由 Worker 终止/对账 |
| `CANCELED` | 已取消 | Worker 已确认取消终态；不代表目标数据回滚 |
| `LOST` | 状态丢失 | 无法确认最终结果；目标可能已写入，必须进入恢复门禁 |

`data_effect`：

| 后端值 | 中文标签 | UI 说明 |
|---|---|---|
| `NONE` | 未发现目标写入 | 有可靠证据证明未写入；仍不代表可绕过其他门禁 |
| `POSSIBLE` | 可能已写入 | Writer 可能启动或中断；按部分写入处置 |
| `CONFIRMED` | 影响已确认 | 表示目标影响已测得（可为 0 行），内容是否正确看核验状态 |
| `UNKNOWN` | 影响未知 | 无法形成可靠结论；按最保守路径恢复 |

`verification_state`：

| 后端值 | 中文标签 | UI 说明 |
|---|---|---|
| `NOT_STARTED` | 尚未核验 | DataX 尚未满足核验前提或进程提前结束 |
| `VERIFYING` | 核验中 | oracle 正在工作 |
| `PASSED` | 核验通过 | 独立计数和规范化摘要均符合契约 |
| `FAILED` | 核验不一致 | 已形成结论且源/目标不匹配 |
| `INCONCLUSIVE` | 核验无结论 | 证据不足、源不再静默或核验器异常；不能按成功处理 |

三个字段必须并列呈现并同时使用文字、图标和颜色表达。表格、图表、Toast 和详情页使用同一中文标签，不得把 DataX 退出码、单独的 `CONFIRMED` 影响或 `INCONCLUSIVE` 混称“成功”。

`target_exclusivity_status`：

| 后端值 | 中文标签 | UI 说明 |
|---|---|---|
| `ACTIVE` | 声明有效 | 仍须满足未撤回且目标快照在 `valid_until` 前读完；不是外部写入未发生的技术证明 |
| `REVOKED` | 声明已撤回/窗口已报告破坏 | 展示 `revoked_at/reason`；非终态执行不能继续成为成功 |
| `EXPIRED` | 声明已过期 | 展示 `valid_until` 与 `VALIDITY_WINDOW_EXPIRED`；必须走对应失败/恢复路径 |

## 7. 校验与错误呈现

### 7.1 校验层级

1. **输入时校验**：格式、长度、范围和必填项。
2. **离开字段校验**：名称唯一性、端口和组合字段。
3. **服务端保存校验**：权限、项目边界、乐观锁和资源状态。
4. **任务校验**：方向授权、TransferPolicy、真实连接、数据源修订、元数据、映射、类型、目标存在性、安全画像、可核验能力、参数和 Runtime 能力；不以目标当时为空作为发布条件。
5. **运行前校验**：发布版本、方向授权/TransferPolicy、数据源与 Schema 漂移、源静默
   确认、目标外部独占声明版本/有效期/当前状态、按规范化物理表身份的同目标互斥、
   Worker/Runtime/oracle 可用性和幂等键。
6. **Worker 启动前校验**：持有目标互斥权并服务端实测目标零行，生成 `target_empty_evidence`；失败时不得启动 DataX。

客户端校验用于及时反馈，不能替代服务端校验。

### 7.2 错误消息结构

错误消息统一包含：

- **发生了什么**：例如“目标字段 `amount` 精度不足”；
- **为什么**：例如“源字段为 DECIMAL(18,2)，目标字段为 NUMERIC(10,2)”；
- **如何处理**：例如“请预先扩大目标字段或选择其他目标字段”；
- **定位信息**：步骤、字段、稳定错误码和 request_id。

禁止使用：

- “操作失败，请重试”作为唯一信息；
- 数据库原始异常、堆栈、完整 JDBC URL 或明文凭据；
- 把未知、超时或断线显示成成功；
- 自动改写用户映射后不提示。

## 8. 危险操作与防误触

| 操作 | 风险 | UI 保护 |
|---|---|---|
| 运行 | 一次性全量 insert，源变化、目标非空或平台外目标写入会破坏正确性 | 展示版本、固定策略；提交源静默确认，以及有版本和截止时间的目标外部独占声明；提供目标撤回/窗口破坏报告；原子预留 TargetNamespace；服务端空表复检 |
| 恢复后再次执行 | 原执行可能已部分写入 | 外部必要处置 → 处置确认 → 独立 RecoveryProbe 空表复检 → VERIFIED gate → 新源静默确认/带新截止时间的目标外部独占声明 → 新 Execution |
| 取消 | 不能回滚已提交数据 | 明确文案；请求态与最终取消态分离 |
| 更换 Reader/源表 | 清空字段选择和映射 | 列出受影响内容，确认后清空 |
| 更换 Writer/目标表 | 清空目标映射 | 列出受影响内容，确认后清空 |
| 发布 | 生成不可变版本 | 展示版本号、哈希短码和配置摘要 |
| 凭据轮换 | 可能使任务不可执行 | 新密码不可回读；必须重新测试连接 |
| 紧急撤销凭据 | 泄露密码仍可能被运行中工作短暂持有；终止后需恢复处置 | 当前仅 Admin API，UI 不得伪造按钮或成功态；未来入口需原因、二次确认、受影响 Execution/RecoveryProbe 摘要和“非即时/无自动回滚”提示 |
| 停用数据源 | 阻止新发布和执行 | 展示引用任务；确认后停用 |
| 归档任务 | 禁止新执行 | 存在 `QUEUED/STARTING/RUNNING/VERIFYING/CANCEL_REQUESTED` 执行时阻断；历史保留 |
| 归档项目 | 整个项目只读 | 输入项目标识确认；存在 `QUEUED/STARTING/RUNNING/VERIFYING/CANCEL_REQUESTED` 执行时阻断 |
| 停用用户 | 用户无法建立新会话 | 展示角色和活动执行；不能停用最后一个 Admin |

高风险操作不得放在行首主按钮；使用明确动词，不使用模糊的“确定”。二次确认不能用颜色作为唯一风险提示。

## 9. 响应式与可访问性

### 9.1 响应式策略

| 视口 | 行为 |
|---|---|
| ≥ 1440 px | 完整侧栏、完整表格和双栏详情 |
| 1280–1439 px | 完整核心流程；次要表格列可收起到列设置 |
| 1024–1279 px | 侧栏折叠；表单单列；表格允许受控横向滚动；任务映射保持可编辑 |

验收至少覆盖 1440×900、1280×720、1024×768 和 390×844。任何视口都不能因溢出遮挡退出登录、返回、错误信息或运行中的取消动作。

### 9.2 可访问性要求

- 核心流程满足 WCAG 2.1 AA 对比度；正文至少 4.5:1，大文本至少 3:1。
- 所有控件有可读标签、帮助文本和错误关联；占位符不能替代标签。
- 键盘可完成登录、数据源表单、任务五步向导、发布、运行确认、日志控制和取消。
- 拖拽排序必须提供上移/下移按钮；焦点顺序与视觉顺序一致。
- 对话框打开后聚焦标题或首个控件，焦点锁定，关闭后返回触发元素。
- 状态变化通过 `aria-live` 适度播报；日志流不逐行抢占读屏器。
- 图表提供同口径表格或摘要；状态不只依赖颜色。
- 可见焦点不能被主题覆盖；触控目标建议不小于 44×44 px。
- 用户选择“减少动态效果”时关闭非必要动画。

## 10. 文案规范

### 10.1 术语统一

| 使用 | 不使用 |
|---|---|

### 10.2 操作反馈示例

- 保存草稿成功：“草稿已保存，尚未校验。”
- 校验成功：“校验通过，可发布新版本。”
- 发布成功：“版本 v3 已发布。发布不会自动运行任务。”
- 运行提交成功：“执行 `EXE-20260730-0012` 已提交，当前排队中；完成 DataX 运行后仍需独立核验。”
- DataX 退出 `0`：“DataX 进程已结束，正在独立核验目标数据。”
- 核验通过：“复制已核验成功，目标记录数与内容摘要符合契约。”
- 核验无结论：“本次核验无法形成结论，不能按成功处理；请保持源表静默并查看恢复建议。”
- 取消请求成功：“取消请求已提交，等待 Worker 确认。”
- 网络不确定：“暂未确认提交结果，正在使用请求标识查询，请勿重复提交。”
- Worker 离线：“执行 Worker 当前不可用，暂不能提交新执行；历史记录仍可查看。”
- 本机启动成功：“本机服务已就绪，正在打开 `http://127.0.0.1:17860`。”
- 前置依赖缺失：“无法启动：需要 Windows 11 x64、WSL2 和 Docker Desktop。请按官方
  指引自行完成安装和许可确认后重新检查。”
- 恢复对账：“本机服务已恢复，正在对账中断前的执行；完成前不能提交新运行。”
- 日志清理：“运行日志已按保留策略清理，执行摘要和审计记录仍保留。”

Toast 仅显示短结果；失败详情、风险和需要用户处理的内容必须在页面消息条或错误抽屉中持续可见。

## 11. UI 数据安全

- 产品前端只使用 `http://127.0.0.1:17860` 同源 API；不得发现、保存或回退到局域网 IP、
  `0.0.0.0`、远程服务器地址。主机端口探测与 Compose 配置验收证明 API、Worker 和
  PostgreSQL 没有宿主映射。
- 浏览器不接收已保存密码、完整连接串、主密钥、完整运行 JSON 或未脱敏日志。
- 密码输入禁止写入 URL、本地存储、会话存储、分析事件和错误上报。
- JSON 预览和版本对比基于后端脱敏表示，不在前端用字符串替换“补做脱敏”。
- 表名、字段名、日志、错误和审计差异全部按不可信文本转义。
- 下载日志必须由服务端生成脱敏文件，并带项目授权和审计。
- 切换项目、退出或权限撤销后，清理对应查询缓存和敏感页面状态。
- 前端不提供任意 SQL、JDBC URL、自定义参数、文件路径或插件上传输入。
- 浏览器页面不直接调用 Docker Desktop、WSL2 或宿主 shell；本机启停只通过受控 Launcher，
  Launcher 的诊断输出进入同一脱敏与大小限制。
