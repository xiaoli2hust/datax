# ADR-0003：不可变任务版本与安全执行

- 状态：Accepted
- 日期：2026-07-30

## 背景

直接执行可编辑任务会让历史结果无法重现；直接拼接 `datax.py` 命令会引入注入、凭据和进程管理风险。

## 决策

- 只有不可变 `JobVersion` 可执行。
- 每个版本保存规范化 JobSpec 哈希、Runtime 和插件版本，并固定源、目标
  `DatasourceRevision`、`EndpointPolicyRevision`、PhysicalEndpointIdentity/TargetNamespace
  和 TransferPolicy `scope_hash`；后续修改数据源、策略或别名不能改变已发布版本。
- 凭据与非秘密连接配置分别版本化。Execution 必须在领取事务内、任何 DNS/JDBC/DataX
  连接前固定实际 `CredentialSecret` 和 `CredentialSecretEnvelope`；只有 `ACTIVE`
  secret 可被新领取。`RETIRED` 不影响已固定运行，`REVOKED/COMPROMISED` 立即禁止解密、
  连接并触发所有引用它的非终态工作终止。旧版本在活动执行完成前不得销毁。
- CredentialSecret 的 AES-256-GCM 数据 AAD 固定绑定组织、项目、Datasource、secret ID/
  版本、AAD schema 和数据算法，明确不含 KEK/Envelope 版本。KEK 轮换通过新增
  CredentialSecretEnvelope 只重包裹 DEK，业务 ciphertext/nonce/AAD 不变。
- API 仅创建执行请求；Worker 是唯一运行态写入者。
- Worker 使用参数数组、独立工作目录、临时 `0600` 配置、资源限额和进程组管理。
- 每次 Attempt 获取单调递增 `fence_epoch`。所有心跳、状态和终态写入都必须同时匹配
  `active_attempt_id`、lease token 哈希和 epoch；失租 Worker 立即失去写权限并终止其
  进程树。
- 进程身份至少记录 host boot ID、PID 启动时间和 cgroup/container identity，不能只凭
  PID/PGID 判断是否为原进程。
- 凭据只在运行时注入，不进入预览、持久化 JobSpec 或日志。
- V1 是安全的一次性全量复制：源端必须从运行前检查开始到独立 oracle 完成始终静默；
  目标表必须经 Worker 实测为空，且 Operator/DBA 必须提交
  `statement_version='1.0'`、有限 `valid_until` 的目标外部独占声明，承诺从最后一次
  空表观察到 oracle 目标一致性读事务结束期间没有平台外 DML/DDL。声明具有
  `ACTIVE/REVOKED/EXPIRED` 生命周期；获知窗口破坏时由 Operator/Admin 通过专用接口报告/
  撤回并写 `TARGET_EXCLUSIVITY_REVOKED`。平台目标锁只串行化平台执行，不能替代该运维
  前提，也不能证明未报告写入不存在；自复制判断和目标锁使用不可变物理表身份，不使用
  可换新的 revision ID。
- DataX 退出码为 0 只会进入 `VERIFYING`；独立 oracle 核验通过后才进入
  `SUCCEEDED`。Oracle `PASSED` 还要求声明仍 `ACTIVE`、未撤回未过期且
  `target_result.snapshot_finished_at <= valid_until`。失败、超时、取消、声明破坏或失联
  后，目标锁进入恢复门禁，不能跳过恢复门禁再次执行。
- V1 不自动重试。Execution 一旦被领取，除 `SUCCEEDED/CONFIRMED/PASSED` 外任何终态
  （包括启动前失败或 `data_effect=NONE`）都进入恢复门禁。恢复责任人完成必要外部处置
  （无需清理时如实记录理由）后，只能由独立 RecoveryProbe/ProbeAttempt 事实队列和自身
  fence 重新验证空表并关闭门禁；
  ExecutionAttempt 不能替代。已经成功的一次性复制不可再次写同一非空 TargetNamespace。

## 后果

- 历史执行可追溯到不可变任务、连接/端点策略修订、物理表身份、精确传输 scope、
  secret/Envelope、运行时制品、连接决策和核验证据。
- 取消、超时、崩溃对账、必要外部处置及其诚实确认成为发布必测项。
- 进程成功不再被伪装成业务复制成功；失败后的部分写入不会被无门槛再次追加。
- KEK 可在不改写数据密文的情况下轮换；紧急 secret 撤销边界可审计且 fail closed。
- 未来自动重试、可重复同步、SQL 或插件执行需要新的幂等与安全设计。
