# ADR-0001：V1 范围与非目标

- 状态：Accepted
- 日期：2026-07-30

## 背景

原始文档同时出现数据源、调度、DAG、插件市场和 AI，无法形成可实现、可验收的第一版。
早期基线还把“单节点”默认理解为一台独立 Linux 主机，但目标使用者没有外部服务器，
需要把宿主、安装入口和网络边界收敛为可在一台 Windows 电脑上真实交付的形态。

## 决策

V1 只交付单组织多项目、MySQL 8/PostgreSQL 15 认证矩阵、安全的一次性离线全量复制、手动触发、直连字段映射、`insert-only`、真实 DataX 执行、独立数据核验、故障恢复门禁、日志状态和审计。

V1 唯一发布认证宿主为 Windows 11 x64。用户通过已签名 `Setup.exe` 安装已签名 Windows Launcher 和
桌面快捷方式，由 Launcher 检查 Docker Desktop + WSL2、幂等启动本机 Compose、等待
健康检查并打开默认浏览器的 `http://127.0.0.1:17860`。不要求外部 Linux 服务器。
Docker Desktop + WSL2 是显式前置依赖；安装器不得静默安装 Docker、代替用户接受许可
或以伪装运行环境规避许可。固定 DataX Runtime 继续运行在 Linux 容器中，因此
`Setup.exe`/Launcher 不等于纯原生单进程产品。

仅 Web 可映射 Windows 宿主 `127.0.0.1:17860`；API、Worker、PostgreSQL 不映射宿主
端口，不支持局域网或公网远程访问。Windows 睡眠、关机、重启或 Docker Desktop 停止时
服务不可用，恢复后必须先对账在途 Execution。多项目和四类角色仍保留用于本机治理、
职责分离和审计，不构成远程多用户服务或 HA 承诺。

一次复制要求源表从运行前检查开始到独立 oracle 完成始终静默，目标表预创建、为空且
可核验，并由 Operator/DBA 提交 `statement_version='1.0'`、有限 `valid_until` 的目标
外部独占声明，承诺从 Worker 最后一次空表观察到 oracle 目标一致性读事务结束期间没有
平台外 DML/DDL。声明具有 `ACTIVE/REVOKED/EXPIRED` 生命周期；获知窗口破坏时必须报告/
撤回。它不是平台技术锁，也不能证明任意瞬时、未报告或已回滚的外部写从未发生。V1
脏数据容忍固定为 `record_count=0`、`percentage=0`。
非空目标追加、动态源表复制、非零脏数据容忍、周期性或可重复同步、AI、调度、DAG、
告警、插件市场、任意 SQL、CDC、多租户和 HA 均排除。外部 Linux 服务器部署、macOS/
Linux/Windows on Arm 宿主认证、局域网/公网服务、纯原生单进程 `.exe`、自动安装 Docker
或自动接受/规避其许可同样排除。具体数据结果与恢复语义由 ADR-0004 定义。

## 后果

- 可以用一个真实纵向链路和独立 oracle 客观验收。
- UI 和数据模型不为未实现功能显示可操作入口。
- Windows 安装器和 Launcher 成为 V1 交付物，但业务事实、复制执行和核验仍由容器内
  API/Worker/PostgreSQL/oracle 负责。
- 安装与 E2E 必须在干净 Windows 11 x64 环境验收；macOS/Linux 上构建成功或手工启动
  Compose 不能替代 Windows 交付证据。
- 电脑停机即服务停机，其他设备不能远程访问；产品和文案必须持续标明本地单节点、非 HA。
- 使用者或其组织负责评估并接受适用的 Docker Desktop 许可，产品自动化不得代替这一决定。
- 产品不能把 DataX 退出码 `0`、写入数或进程终态单独称为复制成功。
- 后续能力必须新建 ADR、威胁模型、契约和测试，不能以参数开关绕过。
