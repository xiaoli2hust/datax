# ADR-0007：Discovery Gate 与工程实施分离

- 状态：Accepted
- 日期：2026-07-30
- 决策者：仓库所有者
- 关联：`PRD-FR-DISC-001`、`ACC-PRD-001`、`docs/06_Codex开发执行计划.md`

## 背景

用户访谈、真实任务样本和设计伙伴试用用于验证“是否值得做、为谁做、哪些流程真正有
价值”。代码、容器、自动测试和内部演示不能生成这些市场与可用性证据。

原基线把 Discovery Gate 同时作为“大范围编码的前置条件”和“试点/发布门禁”。仓库
所有者随后明确要求继续完成 Windows 本地工作站工程实现。若仍把二者视为同一个门禁，
文档会一边禁止实现、一边要求交付代码，形成无法执行的冲突。

## 决策

1. `PRD-FR-DISC-001` 继续是 V1 试点与发布的必过门禁。当前状态保持
   `NOT_EVIDENCED`，不得用代码、Mock、内部人员体验或自动测试替代。
2. 仓库所有者可以明确授权“风险自担的工程候选实现”。该授权只允许编码、测试和制品
   准备，不代表用户问题已验证，也不把 Discovery Gate 改成 PASS。
3. 在 Discovery Gate 未通过时，工程候选可以继续，但所有状态页、README、验收报告和
   Release 必须明确：
   - 产品价值与工作流仍待真实用户验证；
   - 不得宣称企业试点完成、生产就绪或市场需求已证实；
   - 任何真实用户发现导致的范围变化仍需回到 PRD/ADR/契约重新评审。
4. 公开发布、企业试点批准和 V1 完成声明仍同时要求 Discovery Gate、真实 DataX
   四方向 E2E、独立 oracle、干净 Windows 11 x64、签名/哈希/SBOM、恢复与安全门禁全部
   通过。工程实现通过不能抵消其中任何一项。
5. 没有仓库所有者的明确风险授权时，默认仍不得在 Discovery Gate 前投入大范围横向
   实现。无论是否授权，都禁止编造访谈、样本、设计伙伴或试点结果。

## 后果

- 代码可以按当前所有者指令继续完成，文档不再与执行目标互相阻塞。
- 当前仓库仍不是可发布或可宣称完成的 V1；Discovery 证据必须由未来真实研究补齐。
- 若研究证伪当前假设，已经完成的工程候选可能需要修改或废弃，该返工风险由授权者承担。
