# V1 需求追踪矩阵

| 项 | 值 |
|---|---|
| 文档版本 | 1.0 |
| 基线日期 | 2026-07-30 |
| 范围 | V1 功能、业务规则、非功能要求 |
| 用途 | 防止 PRD、UI、数据、API、实现和测试之间遗漏或漂移 |

## 1. 使用规则

- `01_产品战略与PRD.md` 的 `PRD-* / NFR-*` 是产品需求来源。
- `09_测试与验收标准.md` 的 `UT / CT / IT / E2E / UI / SEC / PERF / REC / OPS` 测试族和证据等级是验证契约；不另建平行产品需求编号。
- 本矩阵连接二者与 UI、数据实体、API 和机器契约。
- 实现 PR 必须填写关联需求、测试 ID 和证据。
- 新增、修改或删除需求时，本文件必须在同一 PR 更新。
- `状态` 在文档基线阶段表示契约是否齐全，不代表代码已经实现。

状态取值：

- `基线`：文档与契约已定义，待实现。
- `实现中`：已有代码但未通过全部门禁。
- `已验收`：最低证据达到 `09` 的要求。
- `阻塞`：缺少外部条件或存在未决风险。

当前所有行均为 `基线`。

## 5. 机器契约追踪

| 契约 | 消费者 | 产生者 | 兼容门禁 |
|---|---|---|---|
| `openapi.yaml` | 前端、API 客户端、契约测试 | Backend API | 语法、示例、实现一致性 |
| `job-spec.v1.schema.json` | 前端任务向导、Backend 校验、Worker 渲染 | Product/Backend | Meta Schema、正反例、版本迁移 |
| `plugin-manifest.v1.schema.json` | 插件列表、表单、Job 校验 | 内置 PluginCatalog | Runtime/插件摘要、参数白名单 |
| `audit-event.v1.schema.json` | Audit 写入、查询、导出 | 所有业务模块 | 必填主体/对象/结果/request_id、脱敏 |

破坏性契约变化必须新增版本，不允许只改实现并继续使用旧版本号。

## 6. Agent V2 追踪

Agent 不进入 V1 完成门禁。`07_Agents工程化方案.md` 中的 `AI-*` 需求必须在启用前另建 V2 追踪矩阵，至少覆盖：

- Provider `unconfigured / configured_not_verified / ready`。
- 无 Provider 时完整手工功能。
- 只读元数据、草稿生成、确定性校验与人工采纳。
- 工具 JSON 契约、项目/RBAC、提示注入和敏感数据最小化。
- Agent Run、工具、模型/Prompt 版本和采纳结果审计。
- Provider 超时、非法输出、成本超限和人工降级。
- 黄金集、安全集和“未授权生产写为 0”的发布门槛。

在 V2 追踪矩阵通过前，UI 不得显示 Agent 为可用 V1 功能。

## 7. 发布时的状态扩展

发布报告从本矩阵复制每行并增加：

- 实现 commit。
- 测试执行时间。
- 环境/镜像/Runtime/插件摘要。
- 证据路径或 CI 链接。
- 状态与缺陷 ID。
- 验收人和日期。

没有证据的行保持“未验收”，不得删除或用“基本完成”替代。
